# Aurora Gallery Android 开发规划

## 一、技术选型分析

### 采用方案：Tauri 2.0 Android

**实际架构**：
```
┌─────────────────────────────────────────────────────┐
│                  Android 应用层                      │
│  ┌─────────────────────────────────────────────┐   │
│  │         React 前端（复用桌面端代码）           │   │
│  │  ┌───────────┐  ┌───────────┐  ┌─────────┐  │   │
│  │  │ 桌面端组件 │  │ Android  │  │  平台   │  │   │
│  │  │ (复用)    │  │ 适配逻辑  │  │ 检测    │  │   │
│  │  └───────────┘  └───────────┘  └─────────┘  │   │
│  └─────────────────────────────────────────────┘   │
│                        │                            │
│              Tauri IPC Bridge                       │
│                        │                            │
│  ┌─────────────────────────────────────────────┐   │
│  │           Rust 后端 (Native)                 │   │
│  │  ┌───────────┐  ┌───────────┐  ┌─────────┐  │   │
│  │  │ MediaStore│  │  缩略图   │  │  路径   │  │   │
│  │  │ JNI 扫描  │  │  生成器   │  │  管理   │  │   │
│  │  └───────────┘  └───────────┘  └─────────┘  │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

**关键设计决策**：
- **未使用独立 `mobile/` 目录**：Android 代码直接集成在现有项目中，通过 `#[cfg(target_os = "android")]` 条件编译
- **复用桌面端组件**：前端直接复用 `FileGrid`、`ImageThumbnail`、`ImageViewer` 等组件，通过 `androidPlatform.ts` 适配
- **未使用 AndroidAdapter 模式**：改为在 `tauri-bridge.ts` 中直接处理 Android 分支逻辑

## 五、关键技术点

### 5.1 Android Scoped Storage 适配

**核心问题**：Android 10+ 的 Scoped Storage 限制应用访问公共目录

**解决方案**：
- 使用 MediaStore API（通过 JNI）扫描图片
- 使用 `ContentResolver.loadThumbnail()` 获取系统缩略图
- 使用 `context.getCacheDir()` / `getFilesDir()` 获取应用私有目录
- `resourceRoot` 设为虚拟值 `android_media_store`，不作为文件路径使用

### 5.2 JNI 调用注意事项

- `jni` crate 0.21 不支持 `get_int_array_elements`，使用 `Bitmap.compress()` + `ByteArrayOutputStream` 替代
- `jbyte` 是 `i8` 不是 `u8`，需要 `buf.iter().map(|&b| b as u8).collect()`
- `JObject` 需转换为 `JByteArray` 才能调用 `get_array_length`
- 使用 `ndk_context::android_context()` 获取 Activity 和 VM

### 5.3 前端 Android 适配模式

**采用方案**：在现有代码中添加 Android 分支，而非创建独立的移动端代码

```typescript
// tauri-bridge.ts - Android 缩略图加载
if (_isAndroid) {
    const result = await invoke('android_get_thumbnail', {
        filePath, cacheRoot: cachePath, imageId: mediaStoreId ?? null
    });
    if (result?.thumbnailPath) {
        return convertFileSrc(result.thumbnailPath);
    }
    return null;
}
// 桌面端：使用 ThumbnailBatcher
```

### 5.4 Serde 序列化约定

**关键**：Rust 结构体必须添加 `#[serde(rename_all = "camelCase")]`，否则前端无法正确读取字段

```rust
#[derive(Clone, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct ThumbnailResult {
    pub path: String,
    pub thumbnail_path: Option<String>,  // → thumbnailPath
    pub width: u32,
    pub height: u32,
}
```

## 六、流畅度优化策略

> **核心原则**：流畅度 > 功耗优化

### 6.1 流畅度目标

| 指标 | 目标值 | 当前状态 |
|-----|-------|---------|
| 缩略图加载 | < 50ms | ✅ 系统缩略图约 10-30ms |
| 滚动帧率 | 60 FPS | ⚠️ 需虚拟滚动优化 |
| 页面切换 | < 100ms | ✅ |
| 图片打开 | < 200ms | ⚠️ 需触摸手势适配 |
| 手势响应 | < 16ms | ⬜ 待开发 |

### 6.2 优化任务清单

| 任务 | 优先级 | 状态 | 说明 |
|-----|:------:|:----:|------|
| 缩略图批量请求 | 高 | ⬜ | 当前逐个请求，需并发控制 |
| 虚拟滚动 | 高 | ⬜ | 大量图片时性能关键 |
| 手势支持 | 中 | ⬜ | 缩放、滑动、双击 |
| 缩略图预生成 | 中 | ⬜ | 可见区域前后预生成 |
| 动态缩略图尺寸 | 低 | ⬜ | 根据滚动状态调整 |
| 内存池管理 | 低 | ⬜ | 代码已有，需集成 |

## 七、功耗优化策略

### 7.1 三级省电模式

| 模式 | 触发条件 | 行为变化 |
|-----|---------|---------|
| **正常模式** | 电量 > 50% | 全功能运行 |
| **省电模式** | 电量 20-50% | 减少并发数、暂停后台任务、降低缩略图质量 |
| **超省电模式** | 电量 < 20% | 单线程、仅本地浏览、禁用预加载、最低画质 |

### 7.2 功耗优化任务

| 任务 | 优先级 | 状态 |
|-----|:------:|:----:|
| 电量监控 API | 中 | ⬜ |
| 充电状态监听 | 中 | ⬜ |
| 智能并发控制 | 低 | ⬜ |
| 任务优先级队列 | 低 | ⬜ |
| 屏幕关闭暂停任务 | 低 | ⬜ |

## 九、风险与建议

### 风险点
1. **Tauri Android 成熟度**：已验证可行，但部分 API 不支持（如窗口管理）
2. **性能优化**：大量图片时需要虚拟滚动和并发控制
3. **权限管理**：Android 存储权限政策变化，需持续关注

### 已验证可行的方案
1. **JNI 调用 MediaStore**：成功扫描 21744 张图片
2. **ContentResolver.loadThumbnail()**：成功获取系统缩略图
3. **条件编译**：`#[cfg(target_os = "android")]` 有效分离平台代码
4. **前端组件复用**：桌面端组件可直接在 Android WebView 中使用
