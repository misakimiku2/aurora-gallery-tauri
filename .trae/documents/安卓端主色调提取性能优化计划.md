# 安卓端主色调提取性能优化计划

## 核心设计：时间驱动 + 并行处理

用户的核心诉求是：**后台任务弹窗、设置面板、通知栏的进度条能保持定期更新（约每秒一次），同时整体提取速度显著提升**。

设计原则：
- 不采用固定批次更新，而是**每隔 1 秒由独立的 reporter 线程汇报进度**
- 实际处理工作由多个 worker 线程并行执行
- Pause/Cancel 控制保持不变（通过 AtomicBool）
- 进度通过共享原子计数器实现，reporter 只读不写

---

## 一、架构变更概览

```
当前架构（单线程串行）:
  for img in images:
    ├─ JNI→Kotlin 缩略图（等待）
    ├─ Rust 颜色提取（CPU 一个核）
    ├─ JNI→通知栏更新（每图一次）
    └─ emit→前端进度（每图一次）
  ❌ 8核平板只用1核
  ❌ 每张图都跨 JNI

优化后架构（并行+定时汇报）:
  ┌─── Reporter Thread ─────────────────────────┐
  │  每隔 1 秒:                                   │
  │    读取 AtomicUsize 进度                       │
  │    → JNI 通知栏更新                            │
  │    → emit 前端进度事件                         │
  │    → 批量写入 DB（累积的结果）                  │
  └──────────────────────────────────────────────┘
          ▲ 只读 AtomicUsize
          │
  ┌─── Worker × 6 (rayon 并行) ──────────────────┐
  │  每个 worker:                                 │
  │    ├─ JPEG? → Rust decoder.scale() 快速解码    │
  │    ├─ PNG?  → JNI Kotlin（保持 alpha）         │
  │    ├─ 颜色提取 (color_thief)                   │
  │    ├─ 结果推入共享队列（Mutex<Vec>）           │
  │    └─ fetched_add(1) 到进度计数器             │
  └──────────────────────────────────────────────┘
```

```rust
// 伪代码结构
let completed = Arc::new(AtomicUsize::new(0));
let results_queue = Arc::new(Mutex::new(Vec::new()));

// 启动 Reporter 线程
let reporter = start_progress_reporter(
    app.clone(),
    total,
    completed.clone(),
    results_queue.clone(),
    pool.clone(),
);

// rayon 并行处理
rayon::scope(|s| {
    for fp in &paths_for_extract {
        if should_stop() { break; }
        let completed = completed.clone();
        let results_queue = results_queue.clone();
        s.spawn(move |_| {
            if should_stop() { return; }
            // 获取缩略图 + 提取颜色
            match process_one_image(fp) {
                Ok(colors) => {
                    results_queue.lock().unwrap().push((fp, colors));
                }
                Err(_) => { /* 标记 error */ }
            }
            completed.fetch_add(1, Ordering::SeqCst);
        });
    }
});

// 等待 reporter 完成
reporter.join();
```

### 步骤 2：实现时间驱动的 Reporter 线程

**文件**: `src-tauri/src/lib.rs`（新增函数）

**函数签名**: 
```rust
fn start_progress_reporter(
    app: AppHandle,
    total: usize,
    completed: Arc<AtomicUsize>,
    results_queue: Arc<Mutex<Vec<(String, Vec<ColorResult>)>>>,
    pool: Arc<ColorDbPool>,
) -> std::thread::JoinHandle<()>
```

**核心逻辑**（每秒循环一次）:

```
loop {
    sleep(1000ms)
    
    // 1. 检查是否取消
    if CANCELLED { break; }
    
    // 2. 读取当前进度
    let current = completed.load();
    
    // 3. 如果较上次有变化，发送进度事件
    if current != last_reported {
        // emit "color-extraction-progress" 到前端
        app.emit("color-extraction-progress", {
            batchId: 1,
            current: current,
            total: total,
            pending: total - current,
            currentFile: "",
            batchCompleted: current >= total
        });
        
        // JNI 更新通知栏
        call_kotlin_update_notification(current, total, is_paused);
        
        last_reported = current;
    }
    
    // 4. 批量写入数据库（从 results_queue 取出累积的结果）
    let batch = drain_results_queue();
    if !batch.is_empty() {
        pool.batch_save_colors(&batch);
    }
    
    // 5. 检查是否全部完成
    if current >= total { break; }
}
```

### 步骤 3：实现 JPEG 快速解码路径

**文件**: `src-tauri/src/lib.rs`（修改缩略图获取逻辑）

**改动**：在 `android_batch_extract_colors` 的缩略图获取部分，根据文件扩展名选择优先级。

```rust
fn try_get_thumbnail(file_path: &str, cache_dir: &Path) -> Result<String, String> {
    // 1. 检查缓存
    if let Some(cached) = check_thumbnail_cache(file_path, cache_dir) {
        return Ok(cached);
    }
    
    // 2. 判断格式，选择最优路径
    let is_jpeg = file_path.to_lowercase().ends_with(".jpg") 
               || file_path.to_lowercase().ends_with(".jpeg");
    
    if is_jpeg {
        // JPEG: Rust 优先（decoder.scale() 快速解码 3-5x）
        match crate::android::generate_thumbnail(file_path, cache_dir) {
            Ok(r) if r.thumbnail_path.is_some() => return Ok(r.thumbnail_path.unwrap()),
            _ => {} // Rust 失败，fallback 到 Kotlin
        }
    }
    
    // 3. PNG/WebP/GIF 或有 alpha 通道的图片: Kotlin 优先
    match call_kotlin_generate_thumbnail(file_path, &cache_dir.to_string_lossy()) {
        Ok(Some(tp)) => return Ok(tp),
        Ok(None) | Err(_) => {} // Kotlin 失败
    }
    
    // 4. 最终 Rust 回退
    crate::android::generate_thumbnail(file_path, cache_dir)?
        .thumbnail_path
        .ok_or_else(|| format!("No thumbnail for {}", file_path))
}
```

### 步骤 4：Worker 内暂停/取消检查点

每个 worker 在处理前后检查暂停和取消标志：

```rust
// 处理前检查
if ANDROID_COLOR_CANCELLED.load(Ordering::SeqCst) { return; }

// 暂停等待
while ANDROID_COLOR_PAUSED.load(Ordering::SeqCst) 
      && !ANDROID_COLOR_CANCELLED.load(Ordering::SeqCst) {
    std::thread::sleep(Duration::from_millis(200));
}

// 暂停后再次检查取消
if ANDROID_COLOR_CANCELLED.load(Ordering::SeqCst) { return; }

// ... 处理图片 ...

// 完成后更新计数器
completed.fetch_add(1, Ordering::SeqCst);
```

## 三、进度更新保证

| 组件 | 更新方式 | 更新频率 |
|------|---------|---------|
| **后台任务弹窗** | 监听 `color-extraction-progress` 事件 | **每秒 1 次** |
| **设置面板进度** | 监听 `color-extraction-progress` 事件 | **每秒 1 次** |
| **通知栏进度** | JNI → `call_kotlin_update_notification()` | **每秒 1 次** |
| **数据库写入** | Reporter 线程批量写入 | **每秒 1 次** |

无论 Worker 处理一张图是 50ms 还是 500ms，Reporter 线程的 1 秒周期是固定的：
- 如果 Worker 很快（50ms/张），1 秒内可能处理了 20 张，Reporter 一次性报告 +20
- 如果 Worker 很慢（500ms/张），1 秒内可能只处理了 2 张，Reporter 一次性报告 +2
- **用户始终看到进度在动，不会卡住**

## 六、风险评估

| 风险 | 缓解措施 |
|------|---------|
| 内存压力（6 线程同时解码） | 复用现有的 `MemoryPressureMonitor`，在高内存压力时让 worker 休眠 |
| SQLite 并发写入 | 改为 Reporter 线程单线程批量写入，避免多线程竞争 |
| rayon scope 中的 panic 传播 | 每个 worker 内部用 `catch_unwind` 包裹 |
