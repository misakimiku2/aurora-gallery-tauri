# 桌面版标签写入不落库问题（待修）

> 状态： **待修**（2026-09-21 记录）。本轮不动 `src/`，遵守「React 版一律不动」纪律（见 [安卓Kotlin版并行开发规划](./Android/Kotlin版/安卓Kotlin版并行开发规划.md) §1）。
> 发现来源： 为 [M4a 清单](./Android/Kotlin版/M4a数据与整理任务清单.md) 的 D14（标签逻辑下沉 Rust 时照搬还是修正桌面现行为）核对 `src/hooks/useTags.ts` 时发现。
> 影响面： **桌面版与 React 安卓版都受影响**（同一份 TS 代码）。数据不是立即丢失，而是「重启后回到改之前」，用户通常以为是没保存成功。

## 一句话

`useTags.ts` 里三条会改文件标签的路径，**只有「删除标签」落库，「重命名标签」和「粘贴标签」都只改内存**，重启（或重新扫描目录）后改动消失。

## 缺陷 1：重命名标签不写数据库

- **位置**：`src/hooks/useTags.ts:163-208`（`handleRenameTag`）
- **现象**：把标签 A 改名为 B → 当前会话里看着是对的 → **重启后文件上的标签变回 A**，而标签词表里却是 B。结果是词表与文件标签分叉：侧栏出现一个计数为 0 的 B，以及一堆本该消失的 A。
- **原因**：该函数只更新 `state.files` / `state.customTags` / `state.tabs` 三份内存态，**全程没有调用 `dbUpsertFileMetadata`**。词表之所以看起来"存住了"，是因为 `customTags` 走 `usePersistence.ts:35-44` 的自动保存进了 user_data blob；而每个文件的 `tags` 存在 `file_metadata.tags` 列里，没人写。
- **对照**：同文件的删除路径 `handleConfirmDeleteTags:39-74` 是**正确**的——它收集 `affectedFileIds` 后逐个调用 `dbUpsertFileMetadata`（`:55-64`）。重命名照着这段补即可。

## 缺陷 2：粘贴标签完全不写数据库

- **位置**：`src/hooks/useTags.ts:83-98`（`handlePasteTags`）
- **现象**：复制某些图的标签 → 粘贴到另外 N 张图 → toast 提示成功 → **重启后这些图上一个标签都没有**。
- **原因**：只做了 `newFiles[id] = { ...file, tags: newTags }` 的内存更新，没有任何落库调用。
- **注**：这条的状态更新写法本身是对的（不可变更新），纯粹是漏了持久化。

## 缺陷 3：重命名里直接改 state 对象（次要，但会引出偶发不刷新）

- **位置**：`src/hooks/useTags.ts:172-176`
- **问题**：`const newFiles = { ...prev.files }` 是浅拷贝，`Object.values(newFiles)` 拿到的仍是**原 state 里的同一批 FileNode 对象**，紧接着 `file.tags = file.tags.map(...)`（`:174`）是在**原地修改 prev state**。
- **后果**：违反 React 不可变约定，依赖引用比较的 `memo` / `useMemo` 可能不重渲染。目前被 `App.tsx:1278` 的 `groupedTags` 依赖数组里那个 `filesVersion` 计数器兜住了，所以看起来没出事——但这是靠运气，不是靠正确性。
- **对照**：`handleConfirmDeleteTags` 与 `handlePasteTags` 都用的是 `newFiles[id] = { ...file, tags: ... }`（新建对象），只有重命名这一处是原地改。

## 缺陷 4：粘贴的 toast 文案硬编码英文（顺带）

- **位置**：`src/hooks/useTags.ts:97` —— `showToast("Tags pasted")`，没走 `t()`，中文界面下会突然蹦英文。同文件其它提示都走了 `t()`（如 `:80` 的 `t('context.copied')`）。

## 修复方向

1. 缺陷 1、2 都照 `handleConfirmDeleteTags:39-74` 的模式补：在 `setState` 的 reducer 里收集受影响的 `fileId`，然后对每个 id 调 `dbUpsertFileMetadata`，传**整行**（`upsert_file_metadata` 是 `ON CONFLICT DO UPDATE` 全字段覆盖，见 `core/src/db/file_metadata.rs:22-29`，漏字段会把数据清空）。
2. 重命名与粘贴都是多文件操作，建议在一个 `Promise.all` 里并发发，并对失败逐条 `console.error`（现有删除路径就是这个写法），不要静默吞掉。
3. 缺陷 3 顺手改成不可变更新（与另外两处对齐）。
4. 缺陷 4 补一个 i18n key。
5. 改完要验：重命名/粘贴 → **重启 App** → 数据还在；以及重命名后侧栏计数正确（分组计数在 `src/App.tsx:1263`）。

## 与 Kotlin 版（M4a）的关系

- **Rust 侧按正确语义实现，不照搬这三个缺陷**（M4a 清单 D14 已拍板：修正）。
- 因此 M4a 的 1.3 一致性对照，基准是「桌面 TS 现行为 **+ 本文件列出的已知偏差**」，不是逐字段等同。偏差项就是：重命名会落库、粘贴会落库。
- 桌面版什么时候修由验收人单独排期，**不阻塞 M4a**。修完之后 1.3 的偏差清单可以清掉，两端行为归一。
