### v2.3.1 迭代记录（相对 v2.3）

真机反馈：点通知栏"停止共享"后，本机服务端已停止（桌面端反向连接随之断开），但安卓端客户端未断开——设置界面停留在"等待桌面端自动连接本机…"，仍可浏览桌面端图片。根因与修复：

1. **监听器注册竞态**：`useLanClientSync` 的状态事件监听用 `isAndroidPlatformCached()` 做注册门槛，而该缓存要等 App 异步初始化完成后才置 true——监听 effect 若先于初始化完成执行（且 `clearConnection` 身份未变），监听器将永不注册。修复：注册阶段不再拦截，仅在事件回调内判断平台。
2. **后台事件丢失兜底**：点通知按钮时 App 通常处于后台，WebView 被挂起，`lan-share-android-status-changed` 事件可能到不了 JS。修复：心跳周期（5s）同步校验本机服务端状态——"本会话中曾运行、现已停止"且仍连着桌面端时彻底断开整条链路（用 `ownServerWasRunningRef` 区分"用户停止共享"与"App 重启后服务端未恢复"两种情形，后者保持现状不误杀）。
3. **阻止半连接**：本机服务端启动失败（如端口占用）时直接报错并中止连接，不再建立"已连接但共享缺失"的半连接（新增翻译 `settings.lanShare.client.ownServerStartFailed`）。

### v2.3 迭代记录（相对 v2.2）

1. **安卓端面板融合（单连接语义）**：移除独立的"本机共享"紧凑状态卡（开启/停止共享），本机共享状态（地址/验证码/在线设备数/复制）融合进"连接桌面端"的连接卡片内；面板上只有一个"断开"按钮（彻底断开）。`AndroidLanServerPanel.tsx` 保留未挂载（与 `AndroidClientPanel` 同策略，供将来恢复独立入口）。

4. **孤儿服务端回滚**：扫码/手动连接失败（验证码错误、网络错误）时，自动回滚本次为配对开启的本机共享，避免留下无人消费的服务端（此前已在运行的服务端不受影响）。

## 一、背景与目标

### 1.1 现状（实现前）

原局域网互联架构是**单向的**：

```
Android ──(HTTP 客户端)──→ 桌面端 (HTTP 服务端)
                              ↑
                      只能浏览桌面端的图片
```

- 桌面端运行 Axum HTTP 服务端（`src-tauri/src/lan_share/`），通过文件系统暴露图片
- 安卓端运行 HTTP 客户端（`src/components/lan-client/`），通过 REST API 浏览桌面端图片
- 安卓端可将本地图片**上传**到桌面端

### 1.2 目标

实现**桌面端连接安卓端**，使桌面端能够浏览安卓设备上的图片：

```
Android (HTTP 服务端) ──→ 桌面端 ──(HTTP 客户端)──→ Android
                        能浏览安卓端的图片
```

### 1.3 功能目标与实现状态

| 目标 | 状态 |
|------|------|
| 安卓端启动 HTTP 服务端，将 MediaStore 图片通过 REST API 暴露 | ✅ 已实现 |
| 桌面端客户端连接入口 | ✅ 扫码融合为主（手动 IP 输入入口已按反馈移除） |
| 双向互联互不干扰（与现有安卓→桌面端连接并存） | ✅ 已实现（含双向融合：一次扫码即双向互联） |
| 息屏保活（前台服务 + WakeLock + WifiLock） | ✅ 已实现（部分机型待验证） |
| 图片浏览（缩略图/原图）与下载到本地 | ✅ 已实现 |
| 多台安卓设备同时连接（桌面端） | ✅ 已实现 |
| 断线/停止共享的桌面端联动 | ✅ 已实现（心跳超时自动清理 + 提示） |

## 三、安卓端服务端实现

### 3.1 文件结构（实际）

```
src-tauri/src/
  android/
    server/
      mod.rs           # 模块入口，导出 LanShareServer
      types.rs         # AndroidLanServerConfig / Info / Status
      media_store.rs   # MediaStore 查询封装（扫描/浏览/搜索/缩略图/原图）
      handlers.rs      # Axum 端点处理函数（认证/浏览/缩略图/原图/搜索/设备/心跳）
      server.rs        # 服务端启动/停止/配置 + JNI 获取本机 IP
    lan_server_commands.rs  # Tauri 命令层 + 前台服务启停 + 通知栏停止回调
  lan_share/
    mod.rs             # types/session/device_manager 平台无关；handlers/server 桌面专属
    types.rs           # Session/ConnectedDevice/BrowseItem 等（两端共享）
    session.rs         # SessionManager（两端共享）
    device_manager.rs  # DeviceManager（两端共享）
```

### 3.2 与桌面端复用代码

直接复用（编译为 Android 目标时同样生效）：

- `lan_share/types.rs` — `Session`、`ConnectedDevice`、`AuthRequest/Response`、`BrowseItem/Response`、`AllImageFoldersResponse` 等
- `lan_share/session.rs` — `SessionManager`（token 校验、过期清理、设备重命名）
- `lan_share/device_manager.rs` — `DeviceManager`（设备注册、活跃更新、在线判定）

重写部分：

- `handlers.rs` — 数据源改为 MediaStore（桌面端为文件系统/数据库）
- `media_store.rs` — 新增 MediaStore 查询封装

### 3.3 线程模型与 JNI

- 所有 JNI 调用统一走 `media_store::with_jni_env(|env, activity| ...)`：在调用线程上 `attach_current_thread` 后执行。
- handler 通过 `tokio::task::spawn_blocking` 调用 MediaStore 查询，避免阻塞 tokio worker。
- 服务端实例存全局 `OnceLock<Arc<RwLock<Option<LanShareServer>>>>`（而非 Tauri State），使通知栏"停止共享"按钮（Kotlin → `Java_com_aurora_gallery_LanShareService_nativeStopLanShare`）也能访问并停止服务端。

### 3.4 MediaStore 查询（实际函数）

```rust
// media_store.rs 实际接口
/// 全量扫描：所有含图文件夹（BUCKET_ID 分组，扁平列表）+ 根目录散落图片
pub fn scan_all() -> Result<(Vec<BrowseItem>, Vec<BrowseItem>), String>;
/// 浏览指定 BUCKET_ID 下的图片（date_modified 倒序）
pub fn browse_bucket(bucket_id: &str) -> Result<Vec<BrowseItem>, String>;
/// 按文件名搜索（_display_name LIKE %q%）
pub fn search_images(query: &str) -> Result<Vec<BrowseItem>, String>;
/// 按 ID 查询单张图片信息
pub fn get_image_info(image_id: i64) -> Result<Option<AndroidImageInfo>, String>;
/// 缩略图 JPEG 字节（MINI_KIND 系统缩略图 → 文件解码回退）
pub fn get_thumbnail_bytes(image_id: i64, cache_dir: &Path) -> Result<Vec<u8>, String>;
/// 原图字节 + MIME（_data 路径直读 → ContentResolver.openInputStream 回退）
pub fn get_image_bytes(image_id: i64) -> Result<(Vec<u8>, String), String>;
```

实现要点：

- 全量扫描复用现有 `crate::android::scan_device_all`（JNI 遍历 Cursor，按 `bucket_id` 分组）
- 文件夹 `BrowseItem`：`path` = BUCKET_ID 字符串，`preview_images` = [封面图片 ID]，`size` = 图片数
- 根目录散落图片：`_data` 父目录为 `/storage/emulated/0`（或 `/sdcard`）的图片
- 缩略图缓存复用 App 本体缓存 `sys_{id}_q80.jpg`（与扫描/相册共享）
- 原图 MIME 按 `mime_type`/扩展名推断，默认 `image/jpeg`

### 3.5 API 端点（实际）

与桌面端保持一致，便于客户端代码复用：

| 端点 | 方法 | path 参数语义 | 说明 |
|------|------|---------------|------|
| `/api/auth/verify` | POST | — | 验证码认证，body 支持 `device_id` 覆盖旧会话、`peer_server` 触发双向配对 |
| `/api/auth/logout` | POST | — | 登出 |
| `/api/all_image_folders` | GET | — | 返回 `{ folders, root_images }`，allow_edit/upload 恒为 false |
| `/api/browse` | GET | BUCKET_ID（空 = 根，返回文件夹 + 根图片） | folders 恒为空（扁平相册模型） |
| `/api/thumbnail` | GET | MediaStore 图片 ID（数字字符串） | 返回 JPEG，`Cache-Control: private, max-age=600` |
| `/api/image` | GET | MediaStore 图片 ID | 返回原图 + 按 MIME 的 Content-Type |
| `/api/search` | GET | `q` 参数 | 按 DISPLAY_NAME LIKE 匹配 |
| `/api/palette` | GET | 任意 | 固定返回 `{ palette: [] }`（兼容客户端） |
| `/api/devices` | GET | — | 在线设备列表 |
| `/api/heartbeat` | GET | — | 心跳，刷新设备活跃时间 |

### 3.6 服务端生命周期与 Tauri 命令

注册于 lib.rs（Android 平台 invoke_handler）：

| 命令 | 功能 |
|------|------|
| `lan_share_android_start(config)` | 绑定 `0.0.0.0:port`，启动 Axum + 清理任务 + Kotlin 前台服务；**幂等**——已在运行时返回当前信息并更新配置，不报"already running"错误 |
| `lan_share_android_stop()` | 停止服务端 + 前台服务，emit `lan-share-android-status-changed` |
| `lan_share_android_get_status()` | 运行状态 / 端口 / 本机 IP / 设备数 |
| `lan_share_android_get_devices()` | 已连接设备列表 |
| `lan_share_android_update_config(config)` | 运行中实时更新配置（验证码/名称） |

`AndroidLanServerConfig`：`{ enabled, port, access_code, server_name }`。本机 IP 获取为**三重回退**：JNI `MainActivity.getLocalIpAddress()`（WifiManager → ConnectivityManager）→ Rust UDP 探测（绑定 0.0.0.0 后 connect 公网地址取出口网卡 IP，不发数据包）→ 127.0.0.1。

### 3.7 前台服务保活（实际）

`LanShareService.kt`：

- 通知渠道 `lan_share`，通知标题"局域网共享中"，内容"桌面端可访问：http://{ip}:{port}"
- `startForeground(..., FOREGROUND_SERVICE_TYPE_DATA_SYNC)`（API 34+ 指定类型）
- `PARTIAL_WAKE_LOCK` + `WIFI_MODE_FULL_HIGH_PERF` WifiLock
- `START_STICKY` 重启策略
- 通知"停止共享"按钮 → `nativeStopLanShare()`（JNI → Rust `stop_server_internal()`）→ 停止服务端并 emit 状态事件；v2.3 起前端 App 级监听该事件，**同步登出桌面端并清理连接状态（彻底断开整条链路）**，设置面板与通知栏状态一致

`MainActivity.kt` 新增：`startLanShareService(port, ip)`（IP 由 Rust 传入，用于通知栏显示真实地址）/ `stopLanShareService()` / `getLocalIpAddress()`（含日志）；`AndroidManifest.xml` 注册 `<service android:name=".LanShareService" android:foregroundServiceType="dataSync" />`。

### 4.2 远程来源统一分发（remoteSource.ts）

### 4.3 客户端 API（androidClientApi.ts，多设备）


### 4.4 连接状态管理（useAndroidClient.ts，多设备）

- **设置模型**：`settings.lanShare.androidClients: AndroidClientConnection[]`（每台设备 `{ key, host, port, accessToken, serverName, connectedAt }`），旧版单设备配置自动迁移；最近设备存 `savedAndroidDevices`
- **每设备独立**：连接恢复、根目录加载（指数退避重试）、心跳（5s）、文件夹浏览、总览刷新、断开（注销注册表 + 清理该设备文件节点）
- **断线自动清理**：心跳连续 3 次失败（约 15s，如手机端"停止共享"）自动移除设备连接、清理文件节点并弹提示"与「xx」的连接已断开"；桌面端面板主动"断开"时另通过 `lan_share_remove_device` 立即踢出服务端会话（手机端心跳 401 即刻清理，无需等待超时）
- **设备名**：优先 `serverName`（手机自报），配对事件携带对端设备名兜底；**面板重命名后同步更新**（更新 `androidClients[].serverName` → 侧边栏/总览标题即时刷新）
- **浏览分发**：文件夹节点携带 `remoteDeviceKey`，浏览/刷新按设备 key 路由到对应客户端
- **总览视图**：历史标记 `__android_folders_root__:<key>`，每台设备独立总览与下拉刷新

## 五、双向连接融合（一次扫码，双向互联）

用户只需在**安卓端扫码一次**，两端自动互相连上（桌面端手动输入入口已按反馈移除）：

```
扫码方向（安卓 → 桌面）：
  1. 安卓端扫码连接桌面端前，自动开启本机共享（若未开启）
  2. 认证请求携带 peer_server = { 手机端口, 手机验证码 }
  3. 桌面服务端收到后 emit `lan-share-peer-pairing` 事件（含对端设备名）
  4. 桌面端前端自动反向连接手机 → 该设备加入侧边栏与已连接设备列表
  5. 手机端面板显示"双向连接已建立：桌面端已自动连接本机"
  6. 桌面端面板显示"双向连接已建立：手机已自动连接本机"
```

防环设计：**自动配对**方向的认证不再携带 peer_server，配对只传播一跳，不会无限互连。

### 5.1 彻底断开语义（v2.2，v2.3 补全闭环）

一次扫码建立的"双向互联"在用户认知中是**一条连接**，因此任何一侧的断开动作都按"彻底断开整条链路"设计：

```
安卓端点击"断开"（连接卡片，全面板唯一断开按钮）
  1. POST /api/auth/logout 登出桌面端服务 → 桌面端设备列表立即移除（设备变化事件驱动）
  2. lan_share_android_stop 停止本机共享服务端 → 前台服务/通知一并停止
  3. 桌面端反向连接心跳失败 ×3（约 15s）→ 侧边栏设备节点自动移除 + 提示
  ⇒ 两个方向全部断开

安卓端通知栏"停止共享"（或任何路径停止本机服务端）
  1. 服务端停止并 emit lan-share-android-status-changed
  2. App 级监听：检测到服务端已停且仍连着桌面端 → 登出桌面端 + 清理连接状态
  3. 兜底（v2.3.1）：若 App 在后台、事件未能送达 WebView，回到前台后
     心跳周期（5s）校验"本机服务端本会话曾运行、现已停止"→ 同样彻底断开
  ⇒ 与"断开"等价，彻底断开

手机端被动丢失连接（桌面端踢出→心跳 401；桌面端服务停止→心跳失败 ×3）
  1. 立即清理本机连接状态 + 提示"与桌面端的连接已断开"
  2. 同步停止本机共享服务端（通知消失）——不再出现"客户端已断、服务端还开着"的中间态（v2.3）
  ⇒ 两个方向全部断开

桌面端点击"断开"（已连接设备列表，任意行）
  1. 注销反向客户端（androidClientRegistry.unregister + POST logout 到手机服务端）
  2. lan_share_remove_device 踢出该设备在桌面端服务端的会话（v2.2 新命令）
  3. 手机端下一次心跳收到 401 → 清理连接 + 停止本机共享（v2.3）
  ⇒ 两个方向全部断开（无需等 15s 超时）
```

- 手机端心跳另外支持**连续 3 次失败**（约 15s，桌面端服务已停止）自动清理连接，UI 不再停留在"已连接"假状态。
- 扫码/手动连接**失败**（验证码错误、网络错误）时，本次为配对自动开启的本机共享会**自动回滚停止**，不留孤儿服务端（v2.3）；此前已在运行的服务端不受影响。

### 5.2 融合方案审查结论（v2.2，v2.3 修订）

对整套融合方案的复查结论（v2.3 面板融合后大部分不对称已被消除）：

| # | 事项 | 结论 |
|---|------|------|
| 1 | ~~手机端"停止共享"与"断开"两个按钮并存~~ | ✅ v2.3 已融合：面板只有一个"断开"按钮；通知栏"停止共享"等价于彻底断开 |
| 2 | ~~桌面端断开后手机端服务端仍运行（通知常驻）~~ | ✅ v2.3 已闭环：手机端 401/心跳失败清理连接时同步停止服务端，不再有中间态 |
| 3 | 多桌面端：手机端服务端支持多个桌面端连接，但手机端客户端同一时间只连接一个桌面端；断开会停掉服务端，影响所有已连桌面端 | 符合"彻底断开"预期；如后续需要"选择性断开"需引入服务端级会话管理 UI |
| 4 | 桌面端关闭"局域网共享"开关后仍可浏览手机图片（反向连接），手机端约 15s 感知并全链路清理 | 有意设计：两个方向各有独立开关语义；手机端清理后桌面端反向连接也随心跳失败自动移除 |
| 5 | `savedAndroidDevices`（最近设备）已无 UI 入口（手动 IP 输入已按反馈移除） | 死数据保留，供将来恢复手动入口时使用（组件代码同样保留） |
| 6 | 手机端 `handlePeerPairing` 的 Android 分支（自动连接对端）实际不可达 | 防环设计的防御性代码：桌面端反向连接不携带 peer_server；保留无害 |
| 7 | 验证码、token、图片数据均在局域网内明文 HTTP 传输 | 与既有桌面端服务设计一致，依赖局域网隔离；如需更高安全可后续加 TLS/设备证书 |
| 8 | App 重启后两端服务端均不自动恢复（settings.enabled 持久化但未自动拉起） | 与桌面端行为一致，见"已知限制" |
| 9 | ~~安卓端独立"本机共享"卡片提供"开启"~~ | ✅ v2.3 已移除：桌面端手动连接入口已移除，无独立开启场景（扫码连接自动开启、失败自动回滚） |

## 十一、已知限制与待办

1. **上传**：桌面端→安卓端上传未实现（范围外，后续可复用现有 upload 逻辑）
2. **视频浏览**：MediaStore 视频未暴露（范围外）

4. **手动连接入口已移除**：桌面端目前只支持扫码融合连接（按用户反馈精简 UI）；如需恢复手动 IP 输入，`AndroidClientPanel.tsx` 组件代码仍保留可直接接回
5. **多设备同时连接（桌面端）**：✅ 已支持——桌面端客户端为多设备架构（`androidClientRegistry` + `androidClients[]`），侧边栏每台设备一个节点，可同时浏览/下载多台安卓设备；手机端服务端同样支持多个桌面端连接（DeviceManager 已支持）
6. **安卓端服务重启**：App 重启后服务端不会自动恢复（settings.enabled 持久化但未自动拉起，与桌面端行为一致）
7. **真机验证**：基本端到端流程（扫码连接/浏览/下载/停止共享联动）已由用户真机验证通过；息屏保活仍需多机型验证；v2.2 的断开彻底化/心跳清理/侧边栏高度精确化、v2.3 的安卓端面板融合四项修复待真机复验
8. **v2.3 融合闭环**：手机端连接丢失（401/心跳失败）时同步停止本机服务端，通知消失；通知栏"停止共享"等价于彻底断开；连接失败自动回滚孤儿服务端（详见 5.1/5.2）
9. **融合方案审查结论**：详见 5.2 节（不对称语义、多桌面边界、明文 HTTP、死数据等 8 项）

## 十二、与原设计方案的差异

| 原设计 | 实际实现 |
|--------|----------|
| `android/server/types.rs` 与桌面端共享请求/响应类型 | 直接复用 `lan_share::types`；`android/server/types.rs` 仅含服务端配置/状态类型 |
| MediaStore 查询全部新写 ContentResolver 查询 | 全量扫描复用现有 `scan_device_all`；bucket 浏览/搜索新写带 selection 的查询 |
| 原图通过 ContentResolver 读取 | 优先 `_data` 文件路径直读（应用已申请 MANAGE_EXTERNAL_STORAGE），ContentResolver 仅作回退 |
| 通知提供"停止共享"快捷操作 | ✅ 实现，且"停止共享"会真正停掉 Rust 服务端（JNI 回调） |
| 设置面板桌面端新增"连接安卓设备"区域 | 已改为**融合单面板**：设备列表按 IP 去重合并进"局域网共享"面板；手动输入入口按反馈移除（组件代码保留可接回） |
| 安卓端服务端开关 UI | ✅ 实现（`AndroidLanServerPanel` 紧凑状态卡，无切换开关，扫码自动开启） |
| 侧边栏"网络"分区增加安卓设备节点 | ✅ 实现；桌面端无设备时显示灰色"移动设备"，有设备时设备名直接作为分区行（不显示 IP），展开形式对齐根文件夹分区且分区互斥 |
| 下载保存到桌面端缓存目录 | 改为用户通过 plugin-dialog 选择保存文件夹（右键菜单"下载到本地"） |
| `browseToFolderNodes` 返回 folders + images | ✅ 一致（安卓端 folders 恒为空，扁平相册模型） |
| 息屏保活仅 Foreground Service + 可选电池优化 | 额外加入 WifiLock + START_STICKY + 通知栏停止共享 |
| 单向连接（两端各自独立配置） | 增加双向连接融合：认证携带 `peer_server`，对端自动反向连接，一次扫码/连接即双向互联 |
| 安卓端取 IP 仅靠系统 API | 三重回退：WifiManager → ConnectivityManager → Rust UDP 探测（修复部分机型显示 127.0.0.1 的问题） |
| 桌面端客户端单设备连接 | 多设备架构：每台设备独立 `AndroidDeviceClient` + `androidClientRegistry`，设置存 `androidClients[]`，侧边栏每台设备一个节点 |
| 安卓端设置面板为开关式 | 改为紧凑状态卡（无切换开关）：扫码自动开启、幂等启动命令，避免"already running"报错；v2.3 起该状态卡不再独立挂载，本机共享状态融合进"连接桌面端"卡片（组件保留可接回） |
| 桌面端拆分"连接安卓设备"独立区域 | 融合为单一"局域网共享"面板：设备列表按 IP 去重合并两个方向的连接，新设备扫码加入；安卓端同样融合为单连接面板（唯一"断开"按钮） |
| 侧边栏设备行显示 IP | 只显示设备名（按反馈移除 IP）；面板重命名后侧边栏即时同步 |
| 设备文件夹展开为独立浮层 | 改为与根文件夹分区一致的内联缩进展开：分区互斥（同一时间只展开一个分区）、列表高度按侧边栏动态计算、滚动条样式统一 |
