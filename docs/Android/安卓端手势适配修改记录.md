## 一、禁用双指缩放整个应用

### 问题
安卓端双指缩放会缩放整个 WebView 页面，而非应用内的内容。

### 修改

#### 1. index.html — viewport meta 标签
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no" />
```
添加 `maximum-scale=1` 和 `user-scalable=no` 禁止 WebView 页面级缩放。

#### 2. index.css — body 样式
```css
body {
  touch-action: manipulation;
}
```
`touch-action: manipulation` 禁止双击缩放，保留正常的滚动和点击操作。

## 二、安卓系统返回按键适配

### 问题
安卓系统的返回按键无论在哪个页面都直接退回桌面，没有对应到软件的后退功能。

### 修改

#### 1. MainActivity.kt — 拦截返回按键
```kotlin
import androidx.activity.OnBackPressedCallback

private fun setupBackPressedHandler() {
    onBackPressedDispatcher.addCallback(this, object : OnBackPressedCallback(true) {
        override fun handleOnBackPressed() {
            val webView = findWebView(window.decorView)
            if (webView != null) {
                webView.evaluateJavascript(
                    "window.dispatchEvent(new Event('android-back-press'));",
                    null
                )
            } else {
                finish()
            }
        }
    })
}
```
在 `onCreate` 中调用 `setupBackPressedHandler()`，拦截返回按键并向 WebView 发送 `android-back-press` 自定义事件。

#### 2. App.tsx — 监听返回按键事件
```typescript
useEffect(() => {
    const handleAndroidBackPress = () => {
        if (state.activeModal.type !== null) {
            setState(s => ({ ...s, activeModal: { type: null } }));
            return;
        }
        if (state.isSettingsOpen) {
            setState(s => ({ ...s, isSettingsOpen: false }));
            return;
        }
        if (showCloseConfirmation) {
            setShowCloseConfirmation(false);
            return;
        }
        if (tab.viewingFileId) {
            closeViewerRef.current();
            return;
        }
        if (tab.isCompareMode) { /* 退出对比模式 */ return; }
        if (tab.history.currentIndex > 0) {
            goBackRef.current();
            return;
        }
        // 根据退出偏好处理
    };
    window.addEventListener('android-back-press', handleAndroidBackPress);
    return () => window.removeEventListener('android-back-press', handleAndroidBackPress);
}, [/* deps */]);
```

优先级：关闭模态框 → 关闭设置 → 关闭确认弹窗 → 关闭图片查看器 → 退出对比模式 → 导航后退 → 退出处理。

## 三、双指缩放调整图标大小

### 问题
需要在主界面和文件夹内用双指缩放调整缩略图大小，而非缩放整个页面。

### 修改

#### 1. 新建 usePinchZoom hook
**文件**：`src/hooks/usePinchZoom.ts`

核心设计：
- 使用**绝对式缩放**（非增量式），记录手势开始时的初始距离，每帧计算 `totalScale = currentDistance / initialDistance`
- 提供 `onPinchStart`、`onPinchZoom(totalScale)`、`onPinchEnd` 回调
- `onPinchStart` 中记录初始缩略图大小 `pinchStartSize`
- `onPinchZoom` 中用 `pinchStartSize * totalScale` 计算新大小，避免增量累积误差

```typescript
interface UsePinchZoomOptions {
  onPinchStart?: () => void;
  onPinchZoom: (totalScale: number) => void;
  onPinchEnd?: () => void;
  minDistance?: number;
}
```

#### 2. FoldersOverview.tsx — 主界面双指缩放
- 新增 `onThumbnailSizeChange` prop
- 使用 `usePinchZoom` hook，缩放范围 100~480

#### 3. FileGrid.tsx — 文件夹内双指缩放
- 使用 `usePinchZoom` hook
- 缩放范围：普通模式 100~480，人物模式 140~450

#### 4. App.tsx — 传递 onThumbnailSizeChange
```tsx
<FoldersOverview
    ...
    onThumbnailSizeChange={(size) => setState(s => ({ ...s, thumbnailSize: size }))}
/>
```

### 为什么不用增量式缩放
增量式 `scaleDelta = currentDistance / previousDistance; newSize = thumbnailSize * scaleDelta` 有两个问题：
1. `thumbnailSize` 依赖 React 状态更新，touchmove 事件频率远高于渲染频率，多帧使用同一个旧值
2. 增量乘法累积浮点误差

绝对式 `totalScale = currentDistance / initialDistance; newSize = pinchStartSize * totalScale` 每帧结果只取决于手势起始状态和当前状态，完全确定性。

## 四、图片查看器手势操作

### 4.1 双指缩放图片

#### 修改文件：ImageViewer.tsx

直接在 ImageViewer 中实现（不使用 usePinchZoom hook），因为需要与现有缩放/平移系统深度集成。

核心逻辑：
- 记录 `pinchStartScale` 和 `pinchStartPos`（手势开始时的缩放和位置）
- 每帧计算 `totalScale = currentDistance / initialDistance`
- `newScale = pinchStartScale * totalScale`
- 以双指中心点为锚点计算位置偏移
- 手势开始时取消正在进行的动画

### 4.2 单指拖动平移图片

条件：图片不是"适应屏幕"缩放时（`Math.abs(scale - 1) > 0.02`），单指拖动可平移图片。

```typescript
const isNotFitMode = () => Math.abs(scaleRef.current - 1) > 0.02;
```

注意：之前的条件 `scale > 1.02` 只允许放大时拖动，改为 `scale !== 1` 后缩小状态也可拖动。

### 4.3 左右滑动翻页

条件：图片处于"适应屏幕"缩放时，单指水平滑动触发翻页。

参数：
- 滑动距离阈值：30px
- 速度阈值：0.2 px/ms

### 4.4 双击切换缩放模式

双击在三种模式间循环切换：

| 模式 | 缩放比例 |
|------|----------|
| 适应屏幕 (fit) | `scale = 1` |
| 原始尺寸 (original) | `scale = 1 / fitScale` |
| 铺满屏幕 (fill) | `scale = 1 / maxScale` |

- 双击检测：两次触摸间隔 < 300ms，距离 < 30px
- 以双击位置为锚点进行缩放（适应屏幕模式居中复位）

## 五、滑动翻页过渡动画（已完成）

### 最终方案：实时双图跟随 + 纯 React state 驱动 CSS transition

#### 核心架构改变

**之前的问题**（3 个）全部源于同一个根因——旧方案在 `touchend`（松手）后才创建过渡图层，且触摸事件处理器存在闭包陈旧值问题。

**新方案**将过渡从"松手后触发"改为"滑动过程中持续存在"，实现手指拖动时新旧两张图实时同步跟随移动。

#### 状态设计

```typescript
const [swipeState, setSwipeState] = useState<{
  direction: -1 | 1;        // 滑动方向
  outgoingUrl: string;       // 当前图片 URL
  incomingUrl: string;       // 相邻图片 URL（预计算）
  offset: number;            // 手指偏移量
  animating: boolean;        // 是否处于松手后的动画阶段
} | null>(null);

// 用 ref 打破闭包，确保 handleTouchEnd 能读到最新 swipeState
const swipeStateRef = useRef(swipeState);
useEffect(() => { swipeStateRef.current = swipeState; }, [swipeState]);
```

#### 三阶段流程

**阶段 1：touchmove — 手指拖动（animating: false）**

在 `handleTouchMove` 中，一旦判定为图片滑动模式（非拖拽、非缩放），立即：
1. 通过 `getAdjacentImageUrl(direction)` 从缓存/文件系统获取相邻图片 URL
2. 设置 `swipeState`，触发渲染两张过渡图片

```
用户向左滑 dx=-100 → direction=-1
  ↓
渲染：
  - 旧图(z-index:3): translate(-100, 0)     ← 跟随手指左移
  - 新图(z-index:1): translate(-100+742, 0) ← 紧贴旧图右侧，一起左移
  - 主图(opacity:0): 隐藏
```

**阶段 2：touchend — 松手判断**

通过 `swipeStateRef.current`（非闭包变量）读取最新状态：
- **超过阈值**（距离 >30px 或速度 >0.2px/ms）：设置 `animating: true` → 触发 CSS transition + 调用导航
- **未超过阈值**：清除 `swipeState` → 两张图消失，主图恢复（回弹效果）

**阶段 3：CSS transition 动画（animating: true）**

纯 React state 驱动，不操作 DOM。渲染层根据 `animating` 计算不同 transform 值：

| 状态 | 旧图 (z-index:3) | 新图 (z-index:1) |
|------|-------------------|-------------------|
| `animating=false` | `translate(offset, 0)` 跟随手指 | `translate(offset-W, 0)` 紧贴旧图旁 |
| `animating=true` | `translate(direction×W, 0)` 滑出屏幕 | `translate(0, 0)` 滑入中心 |

当 `animating` 从 `false` → `true` 的瞬间，transform 值发生跳变，但此时 CSS `transition: transform 0.25s ease-out` 已启用，浏览器自动平滑过渡。

280ms 后定时器清除 `swipeState`，主图（opacity 恢复为 1）显示新图片。

#### 关键技术点

**1. 闭包陈旧值问题**

触摸事件处理器在 `useEffect([slideshowActive])` 中注册，闭包捕获的是初始渲染时的 state 值。解决方案：所有需要被触摸事件读取的动态 state 都通过 ref 同步：

```typescript
// 这些 ref 确保 touchmove/touchend 闭包中始终能读到最新值
const onNextRef = useRef(onNext);      // 导航回调
const onPrevRef = useRef(onPrev);
const sortedFileIdsRef = useRef(sortedFileIds);  // 文件列表
const filesRef = useRef(files);
const fileIdRef = useRef(file.id);           // 当前文件 ID
const swipeStateRef = useRef(swipeState);    // 滑动状态
```

**2. 相邻图片预计算**

`getAdjacentImageUrl()` 函数在 `touchmove` 中每帧调用，直接从 blob 缓存或 `convertFileSrc` 获取 URL，不依赖 React 异步状态更新：

```typescript
const getAdjacentImageUrl = (direction: -1 | 1): string | null => {
  const currentIdx = sortedFileIdsRef.current.indexOf(fileIdRef.current);
  const nextIdx = direction < 0
    ? (currentIdx + 1) % sortedFileIdsRef.current.length
    : (currentIdx - 1 + sortedFileIdsRef.current.length) % sortedFileIdsRef.current.length;
  const adjacentFile = filesRef.current[sortedFileIdsRef.current[nextIdx]];
  return getBlobCacheSync(adjacentFile.path) || convertFileSrc(adjacentFile.path);
};
```

**3. 渲染层 IIFE 模式**

过渡图片的 transform 值需要在渲染时动态计算（依赖容器宽度），使用立即执行函数表达式（IIFE）避免重复逻辑：

```tsx
{!slideshowActive && swipeState && (() => {
  const cw = containerRef.current?.getBoundingClientRect().width || window.innerWidth;
  const outOffset = swipeState.animating ? swipeState.direction * cw : swipeState.offset;
  return <img style={{ transform: `translate(${outOffset}px, 0)`, ... }} />;
})()}
```

#### 已解决的 3 个原始问题

1. ✅ **图片切换卡住** → 使用 `onNextRef`/`onPrevRef`/`swipeStateRef` 打破闭包，导航始终基于最新文件位置
2. ✅ **反向切换错误** → 同上，`sortedFileIdsRef`/`fileIdRef` 确保索引计算准确
3. ✅ **两图不同步** → `swipeState` 在 touchmove 阶段就持续存在，两张图从手指开始滑动时就同时可见并跟随移动
