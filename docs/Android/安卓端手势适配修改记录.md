## 一、禁用双指缩放整个应用

### 问题
安卓端双指缩放会缩放整个 WebView 页面，而非应用内的内容。

### 修改

#### 1. index.html — viewport meta 标签
```html
<meta name="viewport" content="width=device-width, initial-scale=1, maximum-scale=1, user-scalable=no" />
```
添加 `maximum-scale=1` 和 `user-scalable=no` 禁止 WebView 页面级缩放。

#### 2. index.css — body 样式
```css
body {
  touch-action: manipulation;
}
```
`touch-action: manipulation` 禁止双击缩放，保留正常的滚动和点击操作。

## 二、安卓系统返回按键适配

### 问题
安卓系统的返回按键无论在哪个页面都直接退回桌面，没有对应到软件的后退功能。

### 修改

#### 1. MainActivity.kt — 拦截返回按键
```kotlin
import androidx.activity.OnBackPressedCallback

private fun setupBackPressedHandler() {
    onBackPressedDispatcher.addCallback(this, object : OnBackPressedCallback(true) {
        override fun handleOnBackPressed() {
            val webView = findWebView(window.decorView)
            if (webView != null) {
                webView.evaluateJavascript(
                    "window.dispatchEvent(new Event('android-back-press'));",
                    null
                )
            } else {
                finish()
            }
        }
    })
}
```
在 `onCreate` 中调用 `setupBackPressedHandler()`，拦截返回按键并向 WebView 发送 `android-back-press` 自定义事件。

#### 2. App.tsx — 监听返回按键事件
```typescript
useEffect(() => {
    const handleAndroidBackPress = () => {
        if (state.activeModal.type !== null) {
            setState(s => ({ ...s, activeModal: { type: null } }));
            return;
        }
        if (state.isSettingsOpen) {
            setState(s => ({ ...s, isSettingsOpen: false }));
            return;
        }
        if (showCloseConfirmation) {
            setShowCloseConfirmation(false);
            return;
        }
        if (tab.viewingFileId) {
            closeViewerRef.current();
            return;
        }
        if (tab.isCompareMode) { /* 退出对比模式 */ return; }
        if (tab.history.currentIndex > 0) {
            goBackRef.current();
            return;
        }
        // 根据退出偏好处理
    };
    window.addEventListener('android-back-press', handleAndroidBackPress);
    return () => window.removeEventListener('android-back-press', handleAndroidBackPress);
}, [/* deps */]);
```

优先级：关闭模态框 → 关闭设置 → 关闭确认弹窗 → 关闭图片查看器 → 退出对比模式 → 导航后退 → 退出处理。

## 三、双指缩放调整图标大小

### 问题
需要在主界面和文件夹内用双指缩放调整缩略图大小，而非缩放整个页面。

### 修改

#### 1. 新建 usePinchZoom hook
**文件**：`src/hooks/usePinchZoom.ts`

核心设计：
- 使用**绝对式缩放**（非增量式），记录手势开始时的初始距离，每帧计算 `totalScale = currentDistance / initialDistance`
- 提供 `onPinchStart`、`onPinchZoom(totalScale)`、`onPinchEnd` 回调
- `onPinchStart` 中记录初始缩略图大小 `pinchStartSize`
- `onPinchZoom` 中用 `pinchStartSize * totalScale` 计算新大小，避免增量累积误差

```typescript
interface UsePinchZoomOptions {
  onPinchStart?: () => void;
  onPinchZoom: (totalScale: number) => void;
  onPinchEnd?: () => void;
  minDistance?: number;
}
```

#### 2. FoldersOverview.tsx — 主界面双指缩放
- 新增 `onThumbnailSizeChange` prop
- 使用 `usePinchZoom` hook，缩放范围 100~480

#### 3. FileGrid.tsx — 文件夹内双指缩放
- 使用 `usePinchZoom` hook
- 缩放范围：普通模式 100~480，人物模式 140~450

#### 4. App.tsx — 传递 onThumbnailSizeChange
```tsx
<FoldersOverview
    ...
    onThumbnailSizeChange={(size) => setState(s => ({ ...s, thumbnailSize: size }))}
/>
```

### 为什么不用增量式缩放
增量式 `scaleDelta = currentDistance / previousDistance; newSize = thumbnailSize * scaleDelta` 有两个问题：
1. `thumbnailSize` 依赖 React 状态更新，touchmove 事件频率远高于渲染频率，多帧使用同一个旧值
2. 增量乘法累积浮点误差

绝对式 `totalScale = currentDistance / initialDistance; newSize = pinchStartSize * totalScale` 每帧结果只取决于手势起始状态和当前状态，完全确定性。

## 四、图片查看器手势操作

### 4.1 双指缩放图片

#### 修改文件：ImageViewer.tsx

直接在 ImageViewer 中实现（不使用 usePinchZoom hook），因为需要与现有缩放/平移系统深度集成。

核心逻辑：
- 记录 `pinchStartScale` 和 `pinchStartPos`（手势开始时的缩放和位置）
- 每帧计算 `totalScale = currentDistance / initialDistance`
- `newScale = pinchStartScale * totalScale`
- 以双指中心点为锚点计算位置偏移
- 手势开始时取消正在进行的动画

### 4.2 单指拖动平移图片

条件：图片不是"适应屏幕"缩放时（`Math.abs(scale - 1) > 0.02`），单指拖动可平移图片。

```typescript
const isNotFitMode = () => Math.abs(scaleRef.current - 1) > 0.02;
```

注意：之前的条件 `scale > 1.02` 只允许放大时拖动，改为 `scale !== 1` 后缩小状态也可拖动。

### 4.3 左右滑动翻页

条件：图片处于"适应屏幕"缩放时，单指水平滑动触发翻页。

参数：
- 滑动距离阈值：30px
- 速度阈值：0.2 px/ms

### 4.4 双击切换缩放模式

双击在三种模式间循环切换：

| 模式 | 缩放比例 |
|------|----------|
| 适应屏幕 (fit) | `scale = 1` |
| 原始尺寸 (original) | `scale = 1 / fitScale` |
| 铺满屏幕 (fill) | `scale = 1 / maxScale` |

- 双击检测：两次触摸间隔 < 300ms，距离 < 30px
- 以双击位置为锚点进行缩放（适应屏幕模式居中复位）

## 五、滑动翻页过渡动画（未完成）

### 当前状态
已实现双图层滑动过渡框架，但图片切换逻辑存在问题尚未解决。

### 已实现
- `swipeTransition` 状态保存旧图片 URL 和偏移量
- 旧图片图层（z-index: 3）滑出屏幕
- 当前图片图层（z-index: 2）从屏幕外滑入
- CSS transition: `transform 0.3s ease-out`

### 未解决的问题
1. **图片切换卡住**：从图片2滑动到图片3后，无法继续滑动到图片4、5、6...，一直停留在图片3
2. **反向切换错误**：从图片3滑动到上一张时，不会回到图片2，而是直接跳到图片1
3. **两图不同步**：旧图片完全离开屏幕后，新图片才从屏幕外滑入，应该是同步进行的

### 问题分析
核心原因是 `displayUrl` 的更新时序与动画时序不匹配：
- `handleNext()`/`handlePrev()` 调用后，React 需要经过状态更新 → 重渲染 → `displayUrl` 更新的流程
- 在 `displayUrl` 更新之前，当前图片的 `src` 还是旧 URL，无法正确显示新图片
- 已尝试的方案（先切换再动画、useEffect 监听 displayUrl 变化触发动画）均未解决问题

### 可能的解决方向
1. **预加载机制**：在滑动开始时预加载相邻图片，确保切换时 URL 已就绪
2. **独立图片状态**：不依赖 `displayUrl` 的 React 状态更新，而是直接操作 DOM 的 `src` 属性
3. **CSS 动画替代**：使用 CSS `@keyframes` 动画代替 JS 控制的 transform 过渡，避免 React 状态更新时序问题
4. **Canvas 渲染**：使用 Canvas 绘制图片，完全绕过 React 的状态更新机制
