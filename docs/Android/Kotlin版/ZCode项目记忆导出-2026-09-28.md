## 11. build-dir-locked-by-process — 构建目录删不掉的两种归因

| 字段 | 值 |
| --- | --- |
| 名称 | `build-dir-locked-by-process` |
| 类型 | `feedback` |
| 最后更新 | 2026-09-27 12:40 |
| 来源会话 | `sess_0558e9dd-2205-4750-be86-c7a4befd605a` |

2026-09-24 我曾把 `kotlin-app/app/build` 里删不掉的目录误诊为「NAS 侧 ACL 错配」，还自作主张用 init script 把构建重定向到 `build2` 绕行。用户纠正：真实原因是**主电脑的桌面端构建进程占着目录句柄**，被占用才删不掉/改不了名；占用释放后目录即可正常删除（用户已清理，仓库里 build2 也已不存在，且 `kotlin-app/build2/` 已按用户要求加入根 .gitignore 防再冒出来）。

**Why:** SMB 盘上另一台机器（主电脑）的进程锁定的句柄，在本机表现就是「拒绝访问/资源忙」，很容易误判成权限损坏；而绕行目录会污染工作区，用户明确不要。

**How to apply:** 遇到构建目录删不掉：先查/停占用进程（gradle --stop、关桌面端/AS 等再试删），不要下「NAS 权限错配」这类远端结论，也不要建替代构建目录绕行；Y: 是 SMB 网络盘（\\192.168.31.87\git）这一点仍是事实，可作为排查背景。

**补充（2026-09-25）**：gradle 增量缓存损坏（报 `Cannot access output property ... Failed to create MD5 hash`）同一味方：`./gradlew --stop` + `rm -rf app/build` 全清重建即愈；且长期增量构建会让 debug APK 虚胖（35.6MB→清洁重建 29.9MB），体积对比一律用清洁构建数字。

**补充（2026-09-27，第二种归因——服务端名字级损坏）**：M8b 期间 Y 盘 `app/build/tmp/kotlin-classes/debug/androidx/recyclerview/` 出现 `.????000e...`（非法字符）目录——gradle daemon 已停、无 java 进程、8.3 短名/`\\?\UNC\`/改名全失败，且编译过程会重建同样坏条目。这不是句柄占用（空目录 rmdir 正常、文件可改），是 .87 服务端侧的名字损坏，本机无法清理。此时 init 脚本重定向构建目录是**正当绕行**（仓库零改动）：`--init-script` 里 `layout.buildDirectory.set(file("C:/aurora-build-m8b/${project.name}"))`。判别法：rmdir 空目录/改普通文件名能成=非句柄占用，查损坏条目→绕行；.87 侧手动清理后可删 init 脚本（已登记 M8b 清单 §8）。
