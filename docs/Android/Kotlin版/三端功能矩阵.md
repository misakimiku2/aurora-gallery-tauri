## 交互差异对照表

桌面交互到触摸交互的标准映射，Kotlin 版按此实现：

| 桌面 | 安卓（平板/手机） |
|---|---|
| 右键菜单 | 长按菜单（毛玻璃样式沿用） |
| 拖拽 | 长按拖动（仅画布内）；跨组件拖拽无对应 |
| hover 高亮/悬停展开 | 按压态；面板只走按钮开合 |
| Ctrl+点击 多选 | 长按进入选择模式 |
| 滚轮缩放/滚动条 | 捏合三档/触摸滚动 + 下拉刷新 |
| Esc / 鼠标侧键 | 返回手势链（五级优先） |
| 双击标题栏等窗口操作 | 系统 WebView 全屏/沉浸替代 |

## 平台开关现状

> **M7 处置（2026-09-26，D42=a）**：M0 目标「平台差异集中声明」随 React 安卓版退役**不再以原形态兑现**——`src/` 的 isAndroid 运行时分支保留为桌面构建内的死代码（删除=30+ 共享文件重构、桌面回归风险与收益不成比，登记不做）；Kotlin 版的平台差异以本矩阵+设计约定为集中声明。M8+ 手机版若重启 React 形态再评估集中化。

**现状（债务）**： 平台判定散落在 30 余个文件，三种入口混用：

- `isAndroidPlatformCached()` / `isAndroidSync()`（`src/utils/androidPlatform.ts`）
- `_isAndroid`（`src/api/tauri-bridge/state.ts`）
- `isAndroidDevice = resourceRoot === 'android_media_store'`（App.tsx 等处派生）

问题： 没有单一位置能回答「安卓版到底有什么」，每个新功能要逐组件找开关；本矩阵 v1 的现状列就是靠逐文件审计拼出来的。

**目标（规划 M0）**： 平台差异集中声明，本矩阵条目与集中声明一一对应。届时本节改为集中声明文件的索引。

## 维护规则

1. **新功能先登记后实现**： 任何新功能动手前，先在本矩阵登记三端状态（桌面/平板现状、Kotlin 目标、手机目标），需要新里程碑的同步更新规划文档。
2. **落地即更新**： 功能上线后更新对应行的现状列；Kotlin 版推进时更新目标列的实际达成情况。
3. **里程碑引用**： Kotlin 目标列的 M# 编号与[规划文档 §6](./安卓Kotlin版并行开发规划.md#6-迁移路线图) 一一对应，M7 验收以「平板 Kotlin 目标」列全绿（完整/适配/隐藏符合规划，且无待定项）为准。
4. **不对齐项守则**： 新增「隐藏」必须写明理由（触屏无对应/桌面专属/有意取舍），避免变成「没来得及做」。
