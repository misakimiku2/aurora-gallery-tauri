## 2. 拆到什么粒度

判断标准用**「一个文件是否装了多个职责簇」**，而不是行数：

- 该拆：一个文件里能指出 ≥2 个「各自能独立存在」的簇/类（如 `FileGrid.kt` 装了 4 个类）。
- 不必拆：偏大但单一职责（如 `PersonAvatarCrop.kt` 661 行 = 一个裁剪页，`TopicsOverview.kt` 1552 行 = 一个总览页）。这类拆开收益递减，先不动。
- 目标粒度：**单文件 200–500 行**；超过 ~800 行就该再看一眼。

## 5. 通用手法（两刀跑通，后续照抄）

### 5.1 ViewModel 大类：同包扩展函数

Kotlin 没有 partial class，扩展函数是唯一能「不动结构就把一个类的成员摊到多个文件」的手段：

```kotlin
// GalleryViewModelPeople.kt（与 GalleryViewModel 同包）
fun GalleryViewModel.createLocalPerson(name: String, onDone: (Boolean) -> Unit = {}) { … }
internal suspend fun GalleryViewModel.refreshLocalPeople() { … }
```

要点：
- 同包的顶层扩展**无需 import**，原类也不用改结构。
- 扩展函数内访问 companion 成员要限定：`GalleryViewModel.TAG`（直接写 `TAG` 会报 unresolved）。
- uniffi 的 FFI 顶层函数（`upsertPerson` / `listImagesByIds` / `getFileMetadata` …）在新文件里要**重新 import**，它们不会跟着原文件走。
- 只服务于本簇的私有助手降 `internal`（`private` 跨文件不可见）；对外入口保持 `public`。

### 5.2 搬之前的可见性检查

```powershell
# 对该簇用到的成员逐个确认修饰符，private 的要降 internal
Select-String -Path GalleryViewModel.kt -Pattern '^\s{4}(private |internal )?(val|var|fun|suspend fun) <成员名>\b'
```
原则：能不降就不降；本轮只降了 2 处（`debugLog`、`TAG`），注释里写明「为什么降」。

### 5.3 每刀三步验收

1. `.\gradlew :app:compileDebugKotlin`
2. `.\gradlew :app:testDebugUnitTest`（当前 7 个测试文件 / 59 条）
3. 装到模拟器跑相关页面（`phone35` 起步，必要时再上平板形制）

### 5.4 搬移操作注意

按行区间删除时用**内容锚点**定位起止（不要硬编码行号）；写回保持 **CRLF + 无 BOM**：

```powershell
[System.IO.File]::WriteAllLines($f, $out, (New-Object System.Text.UTF8Encoding($false)))
```
否则整文件 diff 会炸。函数结束行匹配用 `^    \}$`（恰好 4 空格），别用 `^\s*\}$`——那会匹配到循环体的闭合括号。

4. 确认 `git status`：**第 1–6 刀全部已入库**（`411630f6c` / `d9d6f4a46` / `13093a995` / `1952e709b`），工作区应是干净的代码改动（只剩文档）。**每刀单独 commit**，不要在未入库的改动上继续叠刀。
5. 开工第一步照旧跑一遍 `.\gradlew :app:compileDebugKotlin :app:testDebugUnitTest` 定论基线。注意：`UP-TO-DATE` 也算绿（任务状态为成功才会跳过），别把它误读成「没编译」。
6. 搬运类工作可委派给受限子智能体 `dev-assistant-scoped`（无删除/无执行/无联网，只写点名文件），编译与 git 操作留在主线程。
7. 脚本搬运的实测坑（第 5、6 刀踩到）：
   - PowerShell 里可选捕获组没参与匹配时 `$Matches[n]` 是 `$null`，写 `if ($sus -ne '')` 会判真 → 给所有函数误加 `suspend`，要写成 `if (-not $sus) { $sus = '' }`；
   - **`-replace` 默认大小写不敏感**：`\bColorTaskState\b` 会把同名的状态字段 `colorTaskState` 一起改坏，凡是「类名」替换一律用 `-creplace`；
   - 按行区间删除后接缝处的空行容易被搬走，写回前看一眼上下两行；
   - `$list.AddRange($array)` 会因 `Object[]` 转型失败，逐项 `Add([string]$x)`。
8. **搬带回调接口的簇先看有没有 `object : Xxx`**：object 表达式不继承外层扩展函数的隐式接收者（lambda 才继承），回调体里所有成员访问会 unresolved，需先 `val vm = this` 捕获（§3 第 6 刀）。AI 任务层的 `AiTaskCallback` / `AiRenameCallback` 属同一类。
9. 模拟器验收走 `adb`：`installDebug` → `adb shell monkey -p com.aurora.gallery.kotlin -c android.intent.category.LAUNCHER 1` 启动 → `uiautomator dump /sdcard/w.xml` + `adb pull` 后正则取 `text=` / `content-desc=` / `bounds=` 定位，再 `input tap x y`。**`adb shell input` 不支持多指**，捏合缩放测不了（§3 验收表已登记为未覆盖）；MCP 的 `android-emulator` 工具集（含 `pinch_zoom`）在本项目会话中不可用，`mobile-ui-tester` 子智能体同样调不到，别指望它补这一项。
