## 1. 拆分原则（延续各里程碑 §1，M8b 特有四条）

1. **形态分叉优先于压缩**：抽屉化与 TopBar 精简（阶段 1）先立——手机侧栏与平板推挤在宿主层分叉（手机=平移抽屉、平板=推挤重排，同一套 Section 内容）；视图打磨（阶段 2）在骨架之上做。禁止把平板推挤直接缩窄当手机形态——那是 React 时代手机「布局灾难」的老路（规划 §2.1：根因是布局模型不匹配，不是适配不足）。
2. **平板零回归红线**：所有形态分支以宽度阈值为界，平板路径代码行为不变；每阶段收尾 avd_tab35 冒烟必做。
3. **组件复用不复制**：抽屉直接复用现有 Section/Pane 组件与 ViewModel 状态，禁止复制出「手机版平行组件」（双份维护即债）。侧栏纪律延续：平板推挤路径与 SidebarPane 动画架构（进度只在 layout 阶段读取、内容恒全宽测量）零改动；手机抽屉容器与手势全部做在宿主层（平移不进 layout——主内容 translationX，FileGrid 不重测不重排）。
4. **沿用项=确认制**：矩阵「沿用（M8+）」条目（表 3 核心交互、表 5 互联、表 6 系统）不需新代码，但必须手机档实测确认后才可标「沿用已确认（M8b）」。

（执行分工惯例：阶段 2/3 互不依赖，拆并行子智能体；主线程做构建/验收/收口。触屏规范 ≥48dp/sp/无 hover 照旧。）
