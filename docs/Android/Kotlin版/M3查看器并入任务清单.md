> 版本： v1.1（2026-09-21 拍板 D7/D8/D9）

## 0. M3 目标与验收（来自规划 §6）

- **范围**：`NativeGalleryView` / `SlideshowView` / `ZoomableImageView`（+ `ThumbnailStripAdapter` 与 `dialogs/` 全套）从 Tauri 壳（`src-tauri/gen/android/`）并入独立 Kotlin 应用（`kotlin-app/`）。
- **验收标准（硬指标）**：全部手势行为**不回退**，逐条对照 [安卓端手势适配修改记录.md](../安卓端手势适配修改记录.md) 的基线走查（单击切换 UI、双指缩放、缩放后拖动、左右滑动翻页、长按、沉浸、系统返回、边缘手势冲突等）。
- **额外目标（本会话补的）**：M3 结束时「在网格点一张图 → 全屏看 → 返回」这条主链路在真机上通。M1 交付的是「能浏览」，M3 交付「能看」——`AppState.viewingFileId` 目前是**声明后零引用**的死字段，M3 要把它用起来。
- **明确不做**：标签/描述/调色板/AI 字段的**编辑与生成**（属 M4/M6）；LAN 图片浏览（`isLan=true` 分支，属 M6）；跨组件拖拽。M3 只保证这些入口**不崩、有占位反馈**。

## 1. 拆分原则

- **搬代码优先于重写**：四个查看器文件 3002 行（`NativeGalleryView` 1935 / `ZoomableImageView` 588 / `SlideshowView` 369 / `ThumbnailStripAdapter` 110）、`dialogs/` 9 个文件 1268 行，全部是**纯代码构建 View**（实测无一处 `R.layout` 引用，只用到 21 个 `ic_lucide_*` 矢量 drawable），迁移成本低、重写风险高。除 D7 与大图管线外，不改实现逻辑。
- **一次任务一次提交**，提交信息带任务号（`M3-2.1: ...`），中断后从最后一个验收通过的任务恢复。
- **只新增不改旧**（延续 M0/M1 纪律）：`src-tauri/`、`src/`、React 版一律不动，React 安卓版照常出货。迁源用**复制**而非 `git mv`——React 版还在用那些文件。
- **每步都在真机或模拟器上跑一遍再提交**，不留「编译通过即完成」。

## 阶段 1：搬进来（先让它能编译）

### 1.1 迁源与包名改造
- **目标**：`NativeGalleryView.kt`(1935) / `ZoomableImageView.kt`(588) / `SlideshowView.kt`(369) / `ThumbnailStripAdapter.kt`(110) + `dialogs/` 全套（9 文件 1268 行）复制到 `kotlin-app/app/src/main/java/com/aurora/gallery/`（保持子包名 `dialogs`，减少 import 改动）。
- **要改的只有三件事**：① `package` 与 `com.aurora.gallery.R` → `com.aurora.gallery.kotlin.R`；② 对 TauriActivity / WebView / Ipc 的任何引用摘掉（**实测这四个文件里 `tauri` 出现 0 次**，`MainActivity.kt`(React 壳) 才有，所以不迁它）；③ `DialogTheme` 接口的实现改由新主题供色（见 1.2）。
- **验收**：`compileDebugKotlin` 通过（允许暂时无人调用）。

### 1.2 资源与主题
- **目标**：补齐 21 个 `ic_lucide_*` 矢量 drawable（查看器 16 个 + dialogs 5 个，源在 `src-tauri/gen/android/app/src/main/res/drawable/`，共 23 个文件，直接复制 XML）与 `R.attr.progressBarStyleLarge` 所需的主题属性。
- **注意**：`AuroraTheme`（Compose 侧，M1 已建）与 `DialogTheme`（View 侧接口）是两套供色通道。M3 让 `NativeGalleryView` 的 `DialogTheme` 实现**从 `AuroraTheme.colors` 取同一批 token**，不要出现第二份色值表——桌面/移动「一张脸」的原则在这里最容易破。
- **验收**：弹窗与抽屉的配色与 M1 网格一致（暗色/亮色各截一处对照）。

### 1.3 编译打通 + 最小可显示
- **目标**：在 D7 选定的宿主里把 `NativeGalleryView` 挂上去，用硬编码的 3 张 `content://` 调 `open(items, 0, null)`，能翻页、能退出。
- **验收**：真机上「看到图 + 能左右翻 + 返回键能关」。

## 阶段 2：接上真数据

### 2.1 ImageItem 构造
- **目标**：`GridModels`/`GalleryViewModel` 的 `Image` → `NativeGalleryView.ImageItem` 的映射。字段对照：`path`（本地为文件路径，M3 无 LAN 可留空）、`fileId`、`name`、`width/height`（**网格已用宽高比算布局，说明库里有**）、`contentUri`（**优先，Scoped Storage 靠它**）、`size/format/createdAt/updatedAt`；`tags/description/sourceUrl/palette/ai*` 一律空（M4/M6 再填）。
- **验收**：抽屉里的元数据区显示正确（大小/格式/日期），标签与 AI 区为空态而非报错。

### 2.2 三条进入路径
- **目标**：① 文件夹内网格点图；② 总览选中的是文件夹——不进查看器（保持 M1 语义）；③ 搜索/日期筛选结果内点图（**startIndex 必须落在过滤后的序列上，不是全库序列**）。
- **验收**：三条路径各自进入后，翻页序列与网格所见顺序一致；筛选态下从第 N 张进入，左右翻不越界到被过滤掉的图。

### 2.3 `viewingFileId` 落地 + 返回后位置保持
- **目标**：把 `TabState.viewingFileId` 用起来——进入时写、关闭时清；关闭查看器后网格**停在原来那张图**（不跳回顶部、不丢滚动位置）。
- **验收**：滚到第 300 张开图 → 关掉 → 网格仍在第 300 张附近，选中态未被清空。

## 阶段 3：接上回调（`Listener` 15 个方法）

### 3.1 返回手势链插级
- **目标**：M1 §7 4.3 的优先级链里，在「退选择模式」之前插入「关查看器」（对齐规划 §6 的「关菜单→退全屏→退编辑→取消选择」）。查看器开着时**系统返回只关查看器，不触发 `goBack()`**。
- **验收**：四层叠加（弹层 + 查看器 + 选择模式 + 搜索）时按优先级逐层退，一次 back 只退一层。

### 3.2 删除与分享（复用 M1 现成链路）
- **目标**：`onDelete` → 复用 4.2 的应用内确认 + `MediaStore.createDeleteRequest`；`onShare` → 复用 `ACTION_SEND_MULTIPLE` 那套（单图版）。删除后**索引对账交给既有 ContentObserver**，并保证查看器自己前进到下一张或退出（不能停在已删的图上）。
- **验收**：真机删一张 → 系统授权 → 查看器落到下一张 → 退出后网格少一张、无幽灵卡片。

### 3.3 其余回调按里程碑占位
- **目标**：`onMore` / `onEditTags` / `onUpdateFile` / `onColorSearch` / `onExtractPalette` / `onCopyToFolder` / `onMoveToFolder` / `onFolderPickerConfirm`（→ M4/M6）、`onLongPress`（→ M4 上下文菜单）、`onImmersiveToggle`（M3 就做，纯系统 UI 控制）、`onNavigate` / `onUpdateSlideshowConfig`（M3 就做）。
- **要求**：未实现的必须**可见地告知**（Toast「随 M4 提供」之类），不能静默无响应——静默失败在真机上会被当成 bug 报回来。
- **验收**：每个入口点下去都有确定反应；幻灯片（`SlideshowView`）能播、能设间隔。

## 阶段 4：大图管线（本里程碑唯一的技术风险）

### 4.1 加载方案选型（需拍板 D8）
- **背景**：查看器现状用 **Coil**（`ImageLoader` + `GifDecoder`/`ImageDecoderDecoder` + 自定义 `MemoryCache`/`DiskCache`）解 `content://`。而 M1 §7 1.3 行记录过一次真机事故：**三星 Tab S8+ 上 Coil 直解 `content://` 触发 `MediaRecoveryDatabase_Impl` 缺失**，当时是靠「ContentResolver 读字节 → Rust `image` crate 生成缩略图」绕开的。同一颗雷可能在大图路径上复现。
- **候选**：A. 沿用 Coil，但喂 `ContentResolver.openInputStream` 的流而非 URI，并关掉 ImageDecoder 恢复分支；B. 自研（`BitmapFactory` + `inSampleSize` 按屏幕尺寸降采样 + 复用 M1 的 `ThumbnailLoader` 内存缓存做「先糊后清」）；C. 保持 Coil 原样，仅在三星机型上降级到 B。
- **要求**：GIF/长图/超大图（长边 4000+）三类都要过；「先糊后清」的观感（先显示缩略图再换高清）要与网格一致。
- **验收**：真机（SM-X808U）上打开上述三类图不崩、不白屏。

### 4.2 内存与快翻压测
- **目标**：连续快翻 50 张、进出查看器 20 次，观察 `NativeHeap` 与是否 OOM；确认回收策略（离屏页是否降级回缩略图）。
- **验收**：无 OOM、无内存台阶式上涨；给出实测数字（MemInfo + gfxinfo）。

## 6. 关键决策点（需验收人拍板）

| # | 决策 | 结论 | 说明 |
|---|---|---|---|
| D7 | 查看器宿主形态 | **③ Compose 条件层 + `AndroidView`**（2026-09-21 拍板） | 在 `App()` 里按 `tab.viewingFileId != null` 条件渲染 `AndroidView(factory = NativeGalleryView)`。生命周期跟组合走，避开 WindowManager 与 Compose 互踩；3.1 返回链天然并入 `MainActivity.kt` 现有的 `BackHandler`（无需 overlay 的按键转发）。代价：全屏沉浸要靠 Activity 窗口标志，`onImmersiveToggle` 的落地位置从「overlay 的 WindowManager 参数」改成「Activity decorView 的 systemUiVisibility」——转屏也不再需要 `updateViewLayout` 那套（Compose 会重测 `AndroidView`），`handleRotation()` 是否仍被需要留到 5.1 实测确认 |
| D8 | 大图加载管线 | **A：沿用 Coil，喂 `ContentResolver.openInputStream` 的字节流**（2026-09-21 拍板） | 保留 Coil 的 GIF 解码、内存/磁盘缓存、View 复用全套机制，只把数据源从 `content://` URI 换成字节流，绕开 M1 §7 1.3 三星事故的触发点（Coil 拿 URI 自己去找 MediaStore 恢复 Provider）。B 案作为 A 在真机仍复现时的退路（届时 GIF 需另配 `ImageDecoder`）。**验证口径见 4.1 验收：SM-X808U 上 GIF/长图/超大图三类不崩不白屏** |
| D9 | 查看器是否吃 `dialogs/` 全套 | **全搬**（2026-09-21 拍板） | 9 文件 1268 行一次搬完，符合 §1「搬代码优先于重写」；`TagEditDialog`/`DescriptionEditDialog`/`SourceUrlEditDialog`/`RenameDialog`/`FolderPickerDialog` 服务 M4/M6，届时直接接线不再二次迁源。代价：M3 期间这 5 个文件是无人调用的死代码，1.1 编译要一次把它们的依赖补齐 |

**1.1 落地的包路径修正**：kotlin-app 的 `namespace` 是 `com.aurora.gallery.kotlin`（不是本清单起草时写的 `com.aurora.gallery`）。查看器落在 `com/aurora/gallery/kotlin/viewer/`，弹窗落在 `viewer/dialogs/`——单列 `viewer` 子包是因为 M1 的 `ui/` 是 Compose 侧、查看器是纯 View 体系，放同一层会混淆两套供色通道的归属。

## 8. 交接要点（供下会话快速接续）

- **M1 的地基直接可用**：`state/AppState.kt`（`TabState.viewingFileId` 就是为查看器留的挂载点）、`GalleryViewModel`（MediaStore 扫描 + ContentObserver 热更新 + `resolveSelectionUris`）、`ThumbnailLoader`（内存 LruCache + 高清磁盘缓存 + Rust `generateThumbnail`）、`ui/components/PullRefreshGrid.kt` 的 `BackHandler` 链。
- **真机测试环境**（2026-09-21 实测）：Tab S8+ 无线 adb，序列号取 `adb devices -l` 里完整的 `adb-R52T701VA1J-…._adb-tls-connect._tcp`；**每条 adb 命令走 TLS 有 5~16s 建连延迟**，「录制 + 注入手势」这类有时序要求的操作必须在**设备端一条 shell** 里排好（`screenrecord ... & sleep 3; input swipe ...; wait`），分两次 adb 调用必然错开；Git Bash 下碰 `/sdcard/...` 要加 `MSYS_NO_PATHCONV=1`。
- **捏合注入钩子**：`am broadcast -a aurora.debug.PINCH --es scale <1.6|0.75> [--es steps N] [--es mode touch]`，走生产回调链，总览与文件夹内都生效。
