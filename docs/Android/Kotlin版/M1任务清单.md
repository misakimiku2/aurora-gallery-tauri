## 0. M1 目标与验收（来自规划 §6）

- **范围**：设计约定文档 + workspace 拆分（前置）；TopBar/TabBar/侧栏骨架；RecyclerView + GridLayoutManager；三档捏合；分组标题；虚拟滚动；编辑模式/多选/范围选择。
- **验收标准（两条硬指标）**：
  1. 9.8 万张图库滚动与捏合换档稳定 **60fps**（对照 React 版实测）；
  2. 返回手势链（关菜单→退全屏→退编辑→取消选择→关标签）生效。
- **额外目标（用户核心诉求）**：M1 结束时平板显示的是**平板上的真实图片（MediaStore）**，不再是 M0 的 `poc-data.db` 桌面子集。

## 1. 拆分原则

- **先数据后 UI**：先打通「MediaStore → Rust → UniFFI → Kotlin」的数据链路（对应「看平板图」诉求），再做网格与骨架。
- **每个任务一次提交**，提交信息带任务号（如 `M1-1.2: ...`），中断后从最后一个验收通过的任务恢复。
- **只新增不改旧**（延续 M0 纪律）：所有产物在 `kotlin-app/` 与 core crate 内新增；`src-tauri/`、`src/`、React 版一律不动，React 安卓版照常出货（dual-run）。

## 阶段 1：数据链路（看平板图的最小闭环，最高优先级）

### 1.1 MediaStore 扫描架构决策（需拍板）
- **问题**：独立 Kotlin 应用里，MediaStore 谁来扫？
  - **方案 A（推荐）**：Kotlin 端用 `ContentResolver` 直扫 MediaStore → 结果经 UniFFI 传给 Rust 入库。单向 `Kotlin→Rust`，复用 M0 已验证的管道，无 JNI 回调。
  - **方案 B**：保留 Rust→JNI→Kotlin 回调（复用现有 `media_store.rs` 的 `scan_device_all_via_kotlin`）。扫描编排在 Rust，但引入双向调用复杂度。
- **参考**：`src-tauri/src/android/media_store.rs`（`AndroidImageInfo`/`AndroidFolderInfo` 结构可复用为共享类型）。
- **验收**：决策写入本清单与规划 §7。

### 1.2 MediaStore 扫描 + 入库 Rust 函数
- **目标**：core crate 提供 UniFFI 导出的入库/查询函数（接收 Kotlin 扫出的原始列表，写 `file_index`，含去重与增量）。
- **参考**：`src-tauri/src/db/file_index.rs`（`batch_upsert`、`get_entries_under_path`）。
- **验收**：UniFFI 绑定生成，Kotlin 端能调；写入的文件夹/图片与 MediaStore 一致。

### 1.3 缩略图链路
- **目标**：MediaStore 缩略图（`MINI_KIND`）优先，不足再走 Rust 解码生成。
- **参考**：`src-tauri/src/android/thumbnail.rs`、`media_store.rs` 的 `get_android_system_thumbnail`。
- **验收**：网格能显示缩略图，不阻塞滚动。

### 1.4 真图上屏
- **目标**：Kotlin 扫 MediaStore → Rust 入库 → Rust 返回分组/列表 → Compose 显示。
- **验收**：平板显示的是**平板真图**，与 M0 桌面子集无关。

## 阶段 2：FileGrid 原生网格

### 2.1 基础网格
- **目标**：`RecyclerView + GridLayoutManager` 渲染图片网格（square 缩略图 + 选中态）。
- **参考**：`src/components/FileGrid.tsx`（网格渲染）、`src-tauri/gen/android/.../NativeGalleryView.kt`（现有 View 体系先例）。
- **验收**：能显示平板图片，滚动流畅。

### 2.2 三档捏合
- **目标**：`GridLayoutManager.spanCount` 动态换档，一次手势至多一档（沿用 M0 三档设计）。
- **参考**：`src/utils/androidThumbnailSizes.ts`（档位换算公式）、`src/hooks/usePinchZoom.ts`。
- **验收**：小/中/大 ≈ 9/6/4 列（平板），换档无跳变。

### 2.3 分组标题
- **目标**：按分组/排序规则渲染分组标题行（sticky）。
- **参考**：`src/components/FileGrid.tsx` 的 `GroupContent`、分组规则 memo。
- **验收**：分组标题与桌面端一致。

### 2.4 虚拟滚动 / 大数据
- **目标**：9.8 万张量级下 RecyclerView 稳定 60fps（RecyclerView 原生回收，天然替代 renderWindow 窗口化）。
- **验收**：9.8 万张滚动不掉帧（对照 React 版）。

### 2.5 布局模式
- **目标**：grid / adaptive / masonry / list 至少先支持 grid（其余 M1 内按优先级补）。
- **参考**：`src/components/FileGrid.tsx` 的 `LayoutMode`。
- **验收**：与矩阵表 1「文件浏览」目标对齐。
