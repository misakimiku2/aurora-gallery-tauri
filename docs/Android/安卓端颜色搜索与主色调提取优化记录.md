# 安卓端颜色搜索与主色调提取优化记录

## 日期
2026-07-16

## 概述

本次会话围绕安卓端颜色搜索功能和 NativeGalleryView 抽屉主色调提取进行了全面优化，涵盖以下主题：

1. **安卓端颜色搜索功能启用**：解除屏蔽，创建移动端颜色选择器面板
2. **颜色选择器面板集成**：从 BottomSheet 改为独立右侧面板，挤压主布局
3. **实时搜索与交互优化**：搜索防抖、面板不自动关闭
4. **预设色块样式统一**：圆角矩形改为圆形，PC 端新增最近使用色块
5. **最近使用颜色实时更新**：搜索时防抖保存
6. **移除冗余关闭按钮**：安卓端颜色选择器右上角关闭按钮
7. **NativeGalleryView 抽屉"提取主色调"按钮**：无主色调时显示按钮替代占位符"-"
8. **呼吸动画 bug 修复**：提取完成后动画不停止
9. **启动时 #ffffff 颜色搜索 bug 修复**：React StrictMode 导致首次渲染检查失效
10. **浏览时自动提取主色调**：设置开关 + Android/PC 双端自动提取
11. **自动提取时的 loading/按钮显示策略**：根据设置和失败状态决定显示内容
12. **呼吸动画可见性优化**：提高对比度

## 二、颜色选择器面板集成

### 2.1 问题

最初颜色选择器使用 BottomSheet 实现，几乎占满整屏，且被左侧树状面板遮挡，只是悬浮在界面上方而不挤压主布局。

### 2.2 方案

将颜色选择器改为与 `MetadataPanel` 相同的独立右侧面板：

- 集成到 `App.tsx` 主布局中
- 呼出时改变文件区域布局（挤压而非悬浮）
- 面板位置与 MetadataPanel 一致
- 安卓端和 PC 端共用同一组件逻辑

## 三、实时搜索与交互优化

### 3.1 实时搜索

- **问题**：原先需要点击下方搜索按钮才会触发搜索
- **方案**：改为 300ms 防抖实时搜索，用户输入颜色值后自动搜索
- 无论主色调数据是否足够搜索结果，都不关闭颜色提取面板

### 3.2 双重防抖机制

| 防抖 | 延迟 | 用途 |
|------|------|------|
| 搜索防抖 | 300ms | 用户输入颜色值后自动触发搜索 |
| 最近使用保存防抖 | 1500ms | 搜索后将颜色添加到最近使用列表 |

## 六、NativeGalleryView 抽屉"提取主色调"按钮

### 6.1 背景

原先当图片没有主色调信息时，抽屉中显示一个占位符"-"，用户体验不佳。

### 6.2 实现

将"-"占位符替换为"提取主色调"按钮：

- 按钮样式与"+编辑标签"按钮类似，使用不同的颜色区分
- 点击按钮触发主色调提取，复用 PC 端 `MetadataPanel` 的提取逻辑
- 通过 JS bridge 实现 Kotlin → JS → Rust 完整链路

### 6.3 跨平台互通链路

```
用户点击按钮（NativeGalleryView）
    │
    ▼
listener?.onExtractPalette(fileId, filePath)
    │
    ▼
MainActivity → evaluateJavascript("window.__androidViewerBridge.onExtractPalette(...)")
    │
    ▼
App.tsx onExtractPalette handler
    ├─ LAN 图片 → lanClientApi.getPalette(path)
    └─ 本地图片 → getDominantColors(path, 8, thumbnailPath)
    │
    ▼
提取成功 → handleUpdateFile(fileId, { meta: { palette: hexColors } })
    │
    ▼
React→Native sync effect → invoke('android_update_native_item', { fileId, updates })
    │
    ▼
NativeGalleryView.updateItem() → updateDrawer() → 显示色块
```

| 文件 | 修改内容 |
|------|---------|
| `NativeGalleryView.kt` | `updateDrawer` 中 palette 为空时显示按钮；`Listener` 接口新增 `onExtractPalette` |
| `MainActivity.kt` | 实现 `onExtractPalette` 回调，通过 `evaluateJavascript` 调用 JS bridge |
| `App.tsx` | `onExtractPalette` bridge handler，复用 PC 端提取逻辑 |

## 七、呼吸动画 bug 修复

### 7.1 问题

用户点击"提取主色调"按钮后，呼吸动画（AlphaAnimation INFINITE）在主色调色块出现后仍不停止，切换图片时依然残留，遮挡下一张图的按钮。

### 7.2 根因分析（多个）

| 根因 | 修复 |
|------|------|
| 提取失败时 `if (hexColors.length > 0)` 阻止状态更新，loading 永不清除 | 移除条件，失败时直接通知 native `palette: []` |
| `navigateFromSwipe` 未清除 `loadingPaletteFileId` | 添加 `loadingPaletteFileId = null` |
| `removeAllViews()` 不取消 INFINITE 动画 | 显式遍历子 view 调用 `clearAnimation()` |
| `close()` 未清除 loading 状态 | 添加 `loadingPaletteFileId = null` |
| palette 已到达但 loading 未清除（时序问题） | 安全兜底：`updateDrawer` 中检查 palette 非空时强制清除 loading |

### 7.3 涉及文件

- `NativeGalleryView.kt`：`updateDrawer`、`navigateFromSwipe`、`close()`、`updateItem`
- `App.tsx`：`onExtractPalette` handler 失败分支

## 八、启动时 #ffffff 颜色搜索 bug 修复

### 8.1 问题

每次重启软件后，都会自动进行 `#ffffff` 颜色搜索，但用户可能没有主色调数据，搜索不到东西。

### 8.2 根因

React **StrictMode** 在 mount 时会执行 effect 两次，导致 `isFirstRender` 模式失效：
- 第一次执行：`isFirstRender` 为 true，设为 false，不触发搜索
- 第二次执行：`isFirstRender` 已为 false，误触发搜索

### 8.3 修复

将 `isFirstRender`（布尔值，判断是否首次渲染）替换为 `lastProcessedHexRef`（引用，比较值是否变化）：

```tsx
// 修复前：isFirstRender 在 StrictMode 下第二次 mount 时已为 false
if (isFirstRender) { isFirstRender = false; return; }

// 修复后：比较当前 hex 与上次处理的 hex，值未变化则跳过
if (lastProcessedHexRef.current === hex) return;
lastProcessedHexRef.current = hex;
```

### 8.4 涉及文件

- `MobileColorPickerSheet.tsx`：替换 `isFirstRender` 为 `lastProcessedHexRef`

## 九、浏览时自动提取主色调

### 9.1 功能描述

在设置-常规中新增"浏览时自动提取主色调"开关，开启后在图片查看器中浏览图片时自动提取主色调信息。

### 9.2 设置项

- **位置**：设置 → 常规
- **默认值**：`true`（默认开启）
- **翻译**：中英文均已添加

| 字段 | 中文 | 英文 |
|------|------|------|
| `autoExtractPalette` | 浏览时自动提取主色调 | Auto Extract Palette |
| `autoExtractPaletteDesc` | 在图片查看器中浏览图片时，自动提取主色调信息 | Automatically extract dominant colors when browsing images in the viewer |

### 9.3 PC 端实现（MetadataPanel）

`MetadataPanel.tsx` 中的自动提取 effect 检查 `settings.autoExtractPalette`：
- 开关关闭时跳过自动提取
- 开关开启时，选中图片无 palette 或 palette 全为 `#000000` 时自动提取
- LAN 图片跳过（远程服务器，本地无法提取）

### 9.4 安卓端实现（App.tsx）

新增 `autoExtractedPaletteRef`（`Set<string>`）防止同一图片重复提取：

```tsx
const autoExtractedPaletteRef = useRef<Set<string>>(new Set());
useEffect(() => {
    if (!useNativeViewer || !nativeViewerActive) {
        autoExtractedPaletteRef.current.clear();
        return;
    }
    if (!state.settings.autoExtractPalette) return;
    const viewingId = activeTab.viewingFileId;
    if (!viewingId) return;
    const file = state.files[viewingId];
    if (!file?.path) return;
    if (file.meta?.palette && file.meta.palette.length > 0) return;
    if (autoExtractedPaletteRef.current.has(viewingId)) return;
    autoExtractedPaletteRef.current.add(viewingId);
    // 异步提取（复用 onExtractPalette 的逻辑）
    (async () => {
        // ... 提取逻辑 ...
        if (hexColors.length > 0) {
            handleUpdateFile(viewingId, { meta: { ...(file.meta || {}), palette: hexColors } });
        } else {
            // 提取失败：通知 native 显示按钮
            invoke('android_update_native_item', {
                fileId: viewingId,
                updates: JSON.stringify({ palette: [], paletteLoadFailed: true }),
            }).catch(() => {});
        }
    })();
}, [useNativeViewer, nativeViewerActive, activeTab.viewingFileId, state.files[...], state.settings.autoExtractPalette]);
```

## 十、自动提取时的 loading/按钮显示策略

### 10.1 设计逻辑

当开启"浏览时自动提取主色调"后，原先的"提取主色调"按钮不需要显示——只有在未开启该功能或自动提取失败后才出现。

| 场景 | 显示内容 |
|------|---------|
| palette 非空 | 主色调色块 |
| palette 为空 + 自动提取开启 + 未失败 | 呼吸动画（loading） |
| palette 为空 + 自动提取开启 + 已失败 | "提取主色调"按钮（fallback） |
| palette 为空 + 自动提取关闭 | "提取主色调"按钮 |

### 10.2 NativeGalleryView 状态变量

```kotlin
/** 正在提取主色调的 fileId，非 null 时抽屉显示 loading 占位 */
private var loadingPaletteFileId: String? = null
/** 用户设置：浏览时自动提取主色调。开启时 palette 为空显示 loading 而非按钮 */
private var autoExtractPalette = false
/** 自动提取失败的 fileId 集合，失败后显示"提取主色调"按钮供用户手动重试 */
private val failedPaletteFileIds = mutableSetOf<String>()
```

### 10.3 updateDrawer 中的 loading 判断

```kotlin
// loading 条件：
// 1. 手动点击按钮触发提取（loadingPaletteFileId 指向当前文件）
// 2. 开启"浏览时自动提取主色调"且 palette 为空且未失败（自动提取即将/正在进行）
val isLoadingPalette = loadingPaletteFileId == item.fileId ||
    (autoExtractPalette && item.palette.isEmpty() && !failedPaletteFileIds.contains(item.fileId))
```

### 10.4 updateItem 中的字段处理

```kotlin
// 同步"浏览时自动提取主色调"开关到 native
if (updates.has("autoExtractPalette")) {
    autoExtractPalette = updates.optBoolean("autoExtractPalette", false)
}
// 处理自动提取失败标记：失败时加入集合显示按钮，成功时从集合移除
if (updates.has("paletteLoadFailed")) {
    if (updates.optBoolean("paletteLoadFailed", false)) {
        failedPaletteFileIds.add(fileId)
    } else {
        failedPaletteFileIds.remove(fileId)
    }
}
// 收到非空 palette 表示提取成功，从失败集合中移除
if (updates.has("palette")) {
    // ... 设置 palette ...
    if (list.isNotEmpty()) {
        failedPaletteFileIds.remove(fileId)
    }
}
```

### 10.5 close() 清理

```kotlin
fun close() {
    // ...
    loadingPaletteFileId = null
    // 清除自动提取失败记录，下次打开重新尝试
    failedPaletteFileIds.clear()
    // ...
}
```

### 10.6 App.tsx sync effect

sync effect 在 updates 中添加 `autoExtractPalette` 字段，并在依赖数组中加入 `state.settings.autoExtractPalette`，使设置变更时立即同步到 native：

```tsx
const updates: Record<string, unknown> = {
    tags: file.tags || [],
    description: file.description || '',
    palette: file.meta?.palette || [],
    autoExtractPalette: !!state.settings.autoExtractPalette,
};
```

### 10.7 App.tsx 提取失败处理

自动提取和手动提取失败时均发送 `paletteLoadFailed: true`：

```tsx
// 自动提取失败
invoke('android_update_native_item', {
    fileId: viewingId,
    updates: JSON.stringify({ palette: [], paletteLoadFailed: true }),
}).catch(() => {});

// 手动提取失败
invoke('android_update_native_item', {
    fileId,
    updates: JSON.stringify({ palette: [], paletteLoadFailed: true }),
}).catch(() => {});
```

## 十一、呼吸动画可见性优化

### 11.1 问题

呼吸动画颜色与背景太接近，浅色和深色模式下都看不清：
- 深色模式：`#1F1F1F` 对面板背景 `#171717`——几乎不可见
- 浅色模式：`#F3F4F6` 对面板背景 `#FFFFFF`——几乎不可见

### 11.2 修复

提高颜色对比度和 alpha 变化范围：

| 属性 | 修复前 | 修复后 |
|------|--------|--------|
| 深色模式色块颜色 | `#1F1F1F` | `#404040`（neutral-700） |
| 浅色模式色块颜色 | `#F3F4F6` | `#D4D4D4`（neutral-300） |
| alpha 范围 | `0.3f ~ 1.0f` | `0.2f ~ 0.9f` |

```kotlin
val drawable = android.graphics.drawable.GradientDrawable().apply {
    shape = android.graphics.drawable.GradientDrawable.OVAL
    setColor(if (isDarkTheme) Color.parseColor("#404040") else Color.parseColor("#D4D4D4"))
}
background = drawable
val anim = android.view.animation.AlphaAnimation(0.2f, 0.9f).apply {
    duration = 800
    repeatMode = android.view.animation.Animation.REVERSE
    repeatCount = android.view.animation.Animation.INFINITE
}
startAnimation(anim)
```

## 十三、关键设计决策

### 13.1 为什么使用独立右侧面板而非 BottomSheet

BottomSheet 占屏面积大、遮挡内容、不挤压布局。独立右侧面板与 MetadataPanel 位置一致，打开时挤压文件区域，用户体验更一致。

### 13.2 为什么使用防抖而非直接保存最近使用颜色

每次按键都触发保存会导致频繁的 localStorage 写入和状态更新。300ms 搜索防抖 + 1500ms 保存防抖的方案平衡了响应性和性能。

### 13.3 为什么用 `lastProcessedHexRef` 替代 `isFirstRender`

React StrictMode 在开发模式下会 mount→unmount→mount 组件，导致基于布尔值的首次渲染检查失效。使用值比较（ref 存储上次处理的 hex）可以正确跳过重复处理，兼容 StrictMode。

### 13.4 为什么 `failedPaletteFileIds` 在 close() 时清除而非持久化

失败记录是会话级别的临时状态。下次打开查看器时，React 端的 `autoExtractedPaletteRef` 也会清除，允许重新尝试自动提取。持久化失败状态会导致已修复的图片永远显示按钮。

### 13.5 为什么手动提取失败也要发送 `paletteLoadFailed`

当 `autoExtractPalette` 为 true 时，loading 条件包括 `autoExtractPalette && palette.isEmpty() && !failed`。如果手动提取失败后不标记 `paletteLoadFailed`，loading 会因为第二个条件为 true 而永久显示。发送 `paletteLoadFailed: true` 确保失败后显示按钮而非永久 loading。
