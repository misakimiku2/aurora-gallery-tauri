## 之前代码不更新的根本原因

问题实际上有**两层**，都已修复：

### 第一层：Vite HMR 无法连接（已永久修复 ✅）

**原因**：`hmr.host` 原来是 `'localhost'`，Android 设备无法访问电脑的 `localhost`

**修复**：[vite.config.ts:24](file:///c:/Users/Misaki/Desktop/git/aurora-gallery-tauri/vite.config.ts#L24) 改为 `'0.0.0.0'`

### 第二层：WebView 缓存旧代码（已永久修复 ✅）

**原因**：即使 HMR 连接成功，Android WebView 也会缓存旧的 JS 文件

**修复**：[vite.config.ts:31](file:///c:/Users/Misaki/Desktop/git/aurora-gallery-tauri/vite.config.ts#L31) 添加了 `'Cache-Control': 'no-store'`

这个修复也是**永久的**。

### 第三层：`dist` 目录嵌入 APK 的旧代码（需注意 ⚠️）

**原因**：当 HMR 连接失败时，Tauri Android WebView 会回退到 APK 中嵌入的 `dist` 目录内容。如果 `dist` 是旧的，显示的就是旧代码。

**这个需要你注意**：每次修改前端代码后，如果不确定 HMR 是否生效，运行一次 `npm run build` 就能确保 `dist` 是最新的。

## 以后还会遇到吗？

| 场景 | 是否还会遇到 | 原因 |
|-----|:----------:|------|
| 正常 `npx tauri android dev` 开发 | ❌ 不会 | HMR 配置已修复，代码会热更新 |
| 修改前端代码后 HMR 不生效 | ⚠️ 极少可能 | 如果网络断开或设备断连，HMR 会失败 |
| 修改 Rust 代码后重新编译 | ❌ 不会 | Rust 重新编译不影响前端代码 |
| 首次安装 APK 到设备 | ❌ 不会 | `npm run build` 已在流程中 |
| 长时间不 build 后运行 dev | ⚠️ 可能 | 如果 `dist` 非常旧且 HMR 连接失败 |

## 建议的工作流程

```bash
# 1. 首次开发或大改动后，先 build 确保 dist 最新
npm run build

# 2. 然后启动开发模式
npx tauri android dev
```

只要保持这个习惯，就不会再遇到代码不更新的问题。如果开发过程中发现 HMR 热更新没生效，在 Chrome DevTools Console 里检查是否有 WebSocket 连接错误，或者直接重新运行 `npm run build && npx tauri android dev` 即可。
