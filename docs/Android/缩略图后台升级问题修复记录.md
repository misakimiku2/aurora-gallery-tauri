# Android 缩略图后台升级问题修复记录

## 问题描述

在 Android 端主界面滚动时，文件夹预览图使用了模糊的 MINI_KIND 缩略图作为封面。当 MINI_KIND 返回的缩略图尺寸小于 200px 时，系统会在后台生成高质量缩略图，但生成完成后：

1. **文件夹预览图不会自动更新** — 即使缩略图已生成，主界面的文件夹封面仍然显示模糊的图片
2. **没有升级过渡效果** — 在后台生成缩略图期间，没有加载动画提示用户
3. **重启软件后恢复正常** — 重启后文件夹预览图变清晰，说明缩略图确实已生成并缓存

## 问题分析

### 日志分析

通过分析 adb logcat 前端日志，发现：

```
[Thumbnail] Android result: {..., upgrading: true}  // 返回 upgrading=true
[Thumbnail] Received android:thumbnail-upgraded: {...}  // 事件已接收
[Thumbnail] Upgrade: ... changed= true  // 缓存已更新
```

**关键发现**：`android:thumbnail-upgraded` 事件确实到达了前端，缓存也正确更新了。问题不在事件传递，而在渲染层。

### 根本原因

Android 主界面使用的是 `FoldersOverview.tsx` 中的 `FolderCard` 组件，**不是** `FolderThumbnail` 或 `Folder3DIcon` 组件。

```tsx
// FoldersOverview.tsx 中的 FolderCard 组件（原代码）
const FolderCard = React.memo(({ folder, resourceRoot, ... }) => {
  const [coverSrc, setCoverSrc] = useState<string | null>(null);
  const [coverLoaded, setCoverLoaded] = useState(false);
  // ❌ 没有监听 aurora:thumbnail-upgraded 事件！
  // ❌ 没有升级过渡效果！
  // ❌ coverLoaded=true 后不再重新加载！
  
  useEffect(() => {
    // 加载一次缩略图后就设置 coverLoaded=true，不再更新
    loadCover();
  }, [...]);

  return (
    <div>
      {coverSrc ? <img src={coverSrc} /> : <FolderPlaceholder />}
      {/* 没有升级中的遮罩/spinner */}
    </div>
  );
});
```

**`FolderCard` 完全没有监听 `aurora:thumbnail-upgraded` 事件**，这意味着：

- 即使 `tauri-bridge.ts` 更新了缓存并派发了 DOM 事件，`FolderCard` 根本不知道缩略图已升级
- `coverLoaded` 设置为 `true` 后，组件不会再重新加载缩略图
- 用户看到的始终是模糊的低质量缩略图，直到重启应用

### 之前的错误诊断

最初误以为问题出在 `Folder3DIcon.tsx` 组件（在 Android 上忽略 `previewSrcs` 只显示文件夹图标），但实际上：

| 组件 | 使用场景 | Android 主界面是否使用 |
|------|---------|---------------------|
| `FoldersOverview.tsx` → `FolderCard` | Android 主界面文件夹总览 | ✅ **是** |
| `FolderThumbnail.tsx` → `Folder3DIcon` | 桌面端文件夹预览 | ❌ 否 |
| `FolderIcon.tsx` → `Folder3DIcon`（内嵌） | 桌面端优化文件夹缩略图 | ❌ 否 |
| `shared/Folder3DIcon.tsx` | MetadataPanel 等 | ❌ 否 |

`Folder3DIcon` 和 `FolderThumbnail` 是桌面端组件，在 Android 主界面上根本不会被使用。

## 修复方案

### 修复 FolderCard 组件 — 添加缩略图升级事件监听

**文件**: `src/components/FoldersOverview.tsx`

#### 1. 导入 `isThumbnailUpgrading`

```tsx
import { getThumbnail, isThumbnailUpgrading } from '../api/tauri-bridge';
```

#### 2. 添加 `upgrading` 状态和 `coverImagePathRef`

```tsx
const FolderCard = React.memo(({ folder, resourceRoot, ... }) => {
  const [coverSrc, setCoverSrc] = useState<string | null>(null);
  const [coverLoaded, setCoverLoaded] = useState(false);
  const [upgrading, setUpgrading] = useState(false);  // 新增

  const coverImagePathRef = useRef(folder.coverImagePath);  // 新增：避免闭包问题
  coverImagePathRef.current = folder.coverImagePath;
  // ...
});
```

#### 3. 加载缩略图时检测 upgrading 状态

```tsx
const loadCover = async () => {
  if (folder.coverImagePath && resourceRoot) {
    const cache = getGlobalCache();
    const cached = cache.get(folder.coverImagePath);
    if (cached) {
      setCoverSrc(cached);
      if (isThumbnailUpgrading(folder.coverImagePath)) {  // 新增
        setUpgrading(true);
      }
      setCoverLoaded(true);
      return;
    }

    try {
      const url = await getThumbnail(...);
      if (url) {
        cache.set(folder.coverImagePath, url);
        setCoverSrc(url);
        if (isThumbnailUpgrading(folder.coverImagePath)) {  // 新增
          setUpgrading(true);
        }
      }
    } catch (e) { /* ignore */ }
  }
  setCoverLoaded(true);
};
```

#### 4. 监听 `aurora:thumbnail-upgraded` 事件

```tsx
useEffect(() => {
  const handler = (e: Event) => {
    const { filePath, thumbnailSrc } = (e as CustomEvent).detail;
    if (filePath === coverImagePathRef.current) {
      console.log('[FolderCard] aurora:thumbnail-upgraded:', filePath);
      setCoverSrc(thumbnailSrc);
      setUpgrading(false);
    }
  };
  const failHandler = (e: Event) => {
    const { filePath } = (e as CustomEvent).detail;
    if (filePath === coverImagePathRef.current) {
      setUpgrading(false);
    }
  };
  window.addEventListener('aurora:thumbnail-upgraded', handler);
  window.addEventListener('aurora:thumbnail-upgrade-failed', failHandler);
  return () => {
    window.removeEventListener('aurora:thumbnail-upgraded', handler);
    window.removeEventListener('aurora:thumbnail-upgrade-failed', failHandler);
  };
}, []);
```

#### 5. 添加升级中的过渡效果

```tsx
{upgrading && (
  <div className="absolute inset-0 bg-black/30 flex items-center justify-center z-10 rounded-lg">
    <svg className="animate-spin h-5 w-5 text-white/70" viewBox="0 0 24 24" fill="none">
      <circle className="opacity-25" cx="12" cy="12" r="10" stroke="currentColor" strokeWidth="3" />
      <path className="opacity-75" fill="currentColor" d="M4 12a8 8 0 018-8V0C5.373 0 0 5.373 0 12h4zm2 5.291A7.962 7.962 0 014 12H0c0 3.042 1.135 5.824 3 7.938l3-2.647z" />
    </svg>
  </div>
)}
```

#### 6. re-request 安全网机制

```tsx
useEffect(() => {
  if (!upgrading || !folder.coverImagePath || !resourceRoot) return;
  let cancelled = false;
  let retryCount = 0;
  const maxRetries = 3;
  const retryDelay = 5000;

  const checkUpgrade = async () => {
    if (cancelled || retryCount >= maxRetries) return;
    retryCount++;
    await new Promise<void>(resolve => setTimeout(resolve, retryDelay));
    if (cancelled) return;
    try {
      const thumbnail = await getThumbnail(folder.coverImagePath!, ...);
      if (cancelled) return;
      if (thumbnail && !isThumbnailUpgrading(folder.coverImagePath!)) {
        const cache = getGlobalCache();
        cache.set(folder.coverImagePath!, thumbnail);
        setCoverSrc(thumbnail);
        setUpgrading(false);
      } else if (isThumbnailUpgrading(folder.coverImagePath!)) {
        checkUpgrade();  // 继续重试
      }
    } catch {
      if (!cancelled) checkUpgrade();
    }
  };

  checkUpgrade();
  return () => { cancelled = true; };
}, [upgrading, folder.coverImagePath, folder.coverImageMediaStoreId, resourceRoot]);
```

## 经验总结

1. **确认组件使用场景** — 修复前必须确认哪个组件才是实际渲染的组件。Android 主界面使用的是 `FolderCard`，而非 `FolderThumbnail` 或 `Folder3DIcon`。修改错误的组件不会产生任何效果。

2. **日志是调试的关键** — 通过日志确认事件确实到达前端（`[Thumbnail] Upgrade: changed= true`），但缺少 `[FolderCard]` 日志，说明 `FolderCard` 没有监听事件。

3. **平台组件差异** — Android 和桌面端使用不同的组件渲染文件夹预览图，需要分别确保核心功能在两端都能正常工作。

4. **安全网机制** — re-request 机制可以在事件丢失时作为后备方案，提高系统可靠性。
