# 安卓端局域网客户端模式实现记录

## 概述

本次修改实现了安卓端局域网（LAN）客户端模式，使安卓设备能够作为客户端连接到桌面端的局域网共享服务器，实现跨平台数据互联。

### 功能目标

- **客户端模式**：安卓端不再是"服务器模式"，而是作为客户端连接桌面端服务器
- **网络浏览**：在 TreeSidebar 新增"网络"分区，浏览桌面端图库
- **图片操作**：查看桌面图片缩略图、全屏查看原图、添加到安卓画布
- **上传功能**：将安卓本地图片上传到桌面端指定目录
- **权限保障**：摄像头权限（扫码连接）、网络权限（HTTP 请求）

### 1. `src/components/lan-client/lanClientApi.ts`

LAN 客户端 API 模块，封装所有与桌面服务器的通信。

**核心功能**：

- `setBaseUrl(url)` / `setToken(token)` — 运行时注入服务器地址和会话令牌
- `isConnected()` — 检查是否已连接
- `disconnect()` — 断开连接，清除 token
- `authenticate(code, deviceName)` — 发送访问码验证，获取 token
- `browse(path)` — 浏览远程目录，返回 `{ folders, images, allowEdit, allowUpload }`
- `browseToFolderNodes(path)` — 将 browse 响应转换为 `FileNode[]`（带 `source: 'lan'`）
- `search(query, scope)` — 远程搜索
- `getDevices()` — 获取已连接设备列表
- `getThumbnailUrl(remotePath)` — 生成缩略图 URL（`/api/thumbnail?path=...&token=...`）
- `getImageUrl(remotePath)` — 生成原图 URL（`/api/image?path=...&token=...`）
- `deleteFile(remotePath)` — 删除远程文件
- `uploadFile(file, targetDir, fileName)` — 上传文件到远程目录

**关键设计**：

- 单例模式，全局唯一的 `lanClientApi` 实例
- 401 响应自动清除 token，提示重新连接
- 网络错误有明确提示（连接超时、服务器无响应）

```typescript
// browseToFolderNodes 将远程响应转换为 FileNode
private imageItemToFileNode(item: BrowseItem): FileNode {
  const remotePath = item.path;
  return {
    id: generateId(remotePath),
    parentId: null,
    name: item.name,
    type: FileType.IMAGE,
    path: 'lan://' + remotePath,      // 合成本地标记路径
    remotePath,                        // 真实远程路径
    source: 'lan',                     // 标记为网络来源
    tags: [],
    size: item.size,
    meta: { width: item.width, height: item.height, ... }
  };
}
```

## 网络总览视图（lan-folders-overview）

安卓端点击"网络"分区头部标题区域时，主内容区切换到 `lan-folders-overview` 视图，复用 `FoldersOverview` 组件以卡片网格形式展示桌面端根目录文件夹，与本地相册总览视觉/交互一致。展开箭头仍可独立展开侧边栏内的文件夹列表。

### 关键设计

- **新增 viewMode**：`'lan-folders-overview'` 加入 `HistoryItem.viewMode` / `TabState.viewMode` 联合类型（`src/types.ts`）与 `pushHistory` 签名（`src/hooks/useNavigation.ts`）
- **虚拟 folderId**：`__lan_folders_root__` 作为历史记录占位 ID，类似本地总览的 `__android_folders_root__`
- **复用 FoldersOverview**：传入 `roots={lanRoots}`、`onFolderClick={handleNavigateNetworkFolder}`，卡片网格布局、下拉刷新、捏合缩放、选择模式全部复用
- **LAN 封面图**：`lanClientApi.folderItemToFileNode` 利用 browse 响应的 `preview_images[0]` 设置 `coverImagePath`（`lan://` 前缀），`FolderCard` 识别 `lan://` 前缀走 `lanClientApi.getThumbnailUrl` 加载封面（不走 Tauri `getThumbnail`）
- **根目录散落图片**：桌面端资源根目录下可能直接包含图片（不在子文件夹内）。`applyLanRoots` 辅助函数统一处理根目录加载结果，将散落图片聚合成虚拟文件夹 `__lan_root_images__`（名称"根目录图片"），加入 `lanRoots` 使其在总览视图卡片网格中展示。虚拟文件夹的 `children` 在加载时即填充，`handleNavigateNetworkFolder` 检测到 children 已存在直接 `enterFolder`，不会对虚拟路径发起 browse 请求；`reloadCurrentLanFolder` 也会拦截虚拟文件夹避免无效请求

### App.tsx 接线

```tsx
const handleNavigateNetworkHome = useCallback(() => {
  if (!lanConnected) { handleOpenLanSettings(); return; }
  pushHistory('__lan_folders_root__', null, 'lan-folders-overview', '', 'all', [], null, 0);
}, [pushHistory, lanConnected, handleOpenLanSettings]);

// 统一处理根目录加载结果：文件夹 + 散落图片（聚合成虚拟文件夹）
const applyLanRoots = useCallback((folders, images, allowUpload) => {
  // folders 存入 state.files，加入 rootIds
  // images.length > 0 时创建虚拟文件夹 __lan_root_images__，children 即填充
  // 更新 state.files、lanRoots、lanAllowUpload
}, [setState]);

// 网络总览下拉刷新（不复用本地 handleRefresh）
const handleLanRefresh = useCallback(async () => {
  if (!lanConnected) return;
  setLanLoading(true);
  try {
    const { folders, images, allowUpload } = await lanClientApi.browseToFolderNodes('/');
    applyLanRoots(folders, images, allowUpload);
  } finally { setLanLoading(false); }
}, [lanConnected, setState, applyLanRoots]);
```

### 导航与返回键

- `handleNavigateUp`：LAN 子文件夹无 `parentId` 时回到 `lan-folders-overview`（而非本地 `__android_folders_root__`）；在 `lan-folders-overview` 时直接 return
- `handleAndroidBackPress`：`lan-folders-overview` 与 `folders-overview` 同等处理（在根，落入退出确认）；`browser` 模式下 `current.source === 'lan'` 时按 `parentId` 逐级返回或回 `lan-folders-overview`

### 4. `src/components/lan-client/lanDownload.ts`

网络图片下载到安卓本地缓存的逻辑。

**功能**：

- `downloadLanImage(remotePath, cacheRoot)` — 单张下载，写入 `{cacheRoot}/lan-cache/{id}_{basename}`
- `downloadLanImagesBatched(remotePaths, cacheRoot, onProgress)` — 批量下载，**4 张/批，200ms 间隔**

**关键约束**：

```typescript
const BATCH_SIZE = 4;
const BATCH_DELAY = 200; // ms

// 批量处理逻辑
for (let i = 0; i < remotePaths.length; i += BATCH_SIZE) {
  const batch = remotePaths.slice(i, i + BATCH_SIZE);
  const results = await Promise.allSettled(batch.map(p => downloadLanImage(p, cacheRoot)));
  // 进度回调
  onProgress?.(i + batch.length, remotePaths.length);
  if (i + BATCH_SIZE < remotePaths.length) {
    await new Promise(r => setTimeout(r, BATCH_DELAY)); // 批次间隔
  }
}
```

## 桌面端上传端点

### handlers.rs

**新增 handle\_upload**：

```rust
pub async fn handle_upload(
  State(state): State<AppState>,
  headers: HeaderMap,
  mut multipart: Multipart,
) -> Result<Json<OperationResponse>, Response> {
  // 1. Token 验证
  let token = extract_token(&headers)?;
  state.sessions.validate_token(&token)?;

  // 2. allow_upload 检查
  let config = state.config.read().await;
  if !config.allow_upload {
    return Err(StatusCode::FORBIDDEN.into());
  }

  // 3. 解析 multipart 字段
  let file_field = multipart.next_field().await?;
  let target_dir = multipart.next_field().await?.text().await?;

  // 4. 路径遍历防护
  if has_traversal(&target_dir) || has_traversal(&file_name) {
    return Err(StatusCode::BAD_REQUEST.into());
  }
  let dest_dir = state.root_path.join(&target_dir);
  if !dest_dir.starts_with(&state.root_path) {
    return Err(StatusCode::FORBIDDEN.into());
  }

  // 5. 保存文件
  let dest_file = dest_dir.join(&file_name);
  std::fs::write(&dest_file, &data)?;

  Ok(Json(OperationResponse { success: true, message: "Uploaded".into(), .. }))
}
```

### 第三批修复：按时间/大小排序无效

#### 问题

网络总览中按时间和按大小排序完全无效——升序降序结果相同，且与按名称排序效果一样。

#### 根因

- **按时间排序**：LAN 文件夹的 `createdAt` 字段为空。服务端 `BrowseItem` 没有 `modified_at` 字段，客户端 `folderItemToFileNode` 也没有设置 `createdAt`。
- **按大小排序**：LAN 文件夹的 `size` 字段未定义（服务端用 `size` 存图片数量，但客户端 `FileNode.size` 未设置），排序代码使用 `a.size` 得到 `undefined`。

#### 修复

**1. Rust 服务端 — `BrowseItem` 新增 `modified_at` 字段**

`types.rs`：
```rust
pub struct BrowseItem {
    // ... 现有字段
    #[serde(skip_serializing_if = "Option::is_none")]
    pub modified_at: Option<i64>,
}
```

`handlers.rs` — 全部 15 处 `BrowseItem` 构造点补充 `modified_at`：

| 构造点 | modified_at 来源 |
|---|---|
| `all_image_folders` 数据库路径（文件夹） | 该文件夹下最新图片的 `modified_at` |
| `all_image_folders` 数据库路径（仅视频文件夹） | 文件夹条目的 `modified_at` |
| `all_image_folders` 数据库路径（根目录图片） | 图片的 `modified_at` |
| `all_image_folders` 文件系统路径（文件夹） | 图片文件系统修改时间的最大值 |
| `all_image_folders` 文件系统路径（根目录图片） | 图片文件系统修改时间 |
| browse handler 数据库路径（文件夹/图片） | `entry.modified_at` |
| browse handler 数据库路径（视频） | 文件系统 `metadata().modified()` |
| browse handler 文件系统路径（文件夹） | 文件夹 `metadata().modified()` |
| browse handler 文件系统路径（图片/视频） | `None`（浏览模式不依赖排序） |
| search handler 所有构造点 | `entry.modified_at` 或 `None` |

文件系统路径中 `image_entries` 元组从 4 元组扩展为 5 元组，增加 `Option<i64>` 修改时间字段。

**2. TypeScript 类型 — `BrowseItem` 接口添加 `modified_at`**

`src/lan-share/api.ts` 和 `src/shared/api/types.ts`：
```typescript
export interface BrowseItem {
  // ... 现有字段
  modified_at?: number;
}
```

**3. 客户端转换 — `folderItemToFileNode` 设置 `createdAt`**

`lanClientApi.ts`：
```typescript
private folderItemToFileNode(item: BrowseItem): FileNode {
  return {
    // ... 现有字段
    imageCount: typeof item.size === 'number' ? item.size : 0,
    createdAt: item.modified_at
      ? new Date(item.modified_at * 1000).toISOString()
      : undefined,
  };
}
```

**4. 排序逻辑 — `FoldersOverview.tsx`**

```typescript
const sortedFolderIds = useMemo(() => {
  const sorted = [...folderNodes].sort((a, b) => {
    let res = 0;
    if (sortBy === 'date') {
      res = (a.createdAt || '').localeCompare(b.createdAt || '');
    } else if (sortBy === 'size') {
      res = ((a.imageCount ?? a.size ?? 0) - (b.imageCount ?? b.size ?? 0));
    } else {
      res = (a.name || '').toLowerCase().localeCompare((b.name || '').toLowerCase());
    }
    return res * (sortDirection === 'asc' ? 1 : -1);
  });
  // __lan_root_images__ 固定顶部，不受排序影响
  const rootImgIdx = sorted.findIndex(f => f.id === '__lan_root_images__');
  if (rootImgIdx > 0) {
    const [rootImg] = sorted.splice(rootImgIdx, 1);
    sorted.unshift(rootImg);
  }
  return sorted.map(f => f.id);
}, [folderNodes, sortBy, sortDirection]);
```

- **按时间**：`createdAt`（ISO 字符串）`localeCompare` 排序，`modified_at` Unix 秒 → `new Date(ms).toISOString()` 转换
- **按大小**：`imageCount ?? size ?? 0` 优先使用 `imageCount`（LAN 文件夹的图片数量）
- **升序/降序**：`res * (sortDirection === 'asc' ? 1 : -1)`

### 关键设计决策

1. **`/api/all_image_folders` vs `/api/browse`**：总览视图使用专用端点获取扁平文件夹列表（仅含直接图片/视频的文件夹），而非 `browse('/')` 返回的含中间目录的树结构。与本地相册策略一致。
2. **`modified_at` 取值策略**：数据库路径取该文件夹下最新图片的修改时间（反映内容更新时间，而非文件夹本身创建时间）；文件系统路径取图片文件系统修改时间的最大值。
3. **`imageCount` 作为大小排序依据**：LAN 文件夹的 `size` 字段在服务端存储的是图片数量（`u64`），客户端映射到 `FileNode.imageCount`。大小排序使用 `imageCount ?? size ?? 0` 兼容本地和 LAN。
4. **`__lan_root_images__` 置顶不受排序影响**：排序完成后单独提取并移至首位，确保根目录散落图片虚拟文件夹始终在顶部。
