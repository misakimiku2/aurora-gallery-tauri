# 安卓端主色调提取功能实现记录

## 概述

安卓端的主色调提取功能是在桌面端基础上进行的适配与简化。核心设计原则是：**手动触发、简化流程、避免自动提取影响性能**。安卓端使用 Kotlin JNI 优先生成缩略图，再从缩略图提取颜色，而非桌面端的直接读图方式。

---

## 一、架构总览

### 安卓端 vs 桌面端对比

| 特性 | Android | 桌面端 |
|------|---------|--------|
| 单文件提取 | `android_get_dominant_colors`（通过缩略图） | `get_dominant_colors`（直接读图或缩略图） |
| 批量提取 | `android_batch_extract_colors`（同步循环） | 后台 `color_extraction_worker`（生产者-消费者模型） |
| 暂停 | `android_pause_color_extraction`（AtomicBool） | `pause_color_extraction`（AtomicBool） |
| 恢复 | `android_resume_color_extraction` | `resume_color_extraction` |
| 取消 | `android_cancel_color_extraction`（独有） | 无取消功能 |
| 缩略图生成 | Kotlin JNI 优先，Rust 回退 | Rust 直接处理 |
| 自动提取 | MetadataPanel 中**不自动提取** | 选中图片时自动提取 |
| 进度事件 | `color-extraction-progress`（含 `cancelled` 字段） | `color-extraction-progress`（无 cancelled） |

### 数据流

```
用户点击"开始提取"
    │
    ▼
SettingsModal → androidBatchExtractColors(filePaths, cacheRoot)
    │
    ▼
tauri-bridge.ts → invoke('android_batch_extract_colors')
    │
    ▼
lib.rs → android_batch_extract_colors()
    │
    ├─ 重置 ANDROID_COLOR_PAUSED / ANDROID_COLOR_CANCELLED
    ├─ 将文件添加到数据库 pending 表
    ├─ spawn_blocking 逐个处理：
    │   ├─ 检查取消标志 → 发送 cancelled 事件
    │   ├─ 检查暂停标志 → 循环等待
    │   ├─ 获取缩略图（缓存 → Kotlin JNI → Rust 回退）
    │   ├─ 提取颜色 → 保存到数据库
    │   └─ emit("color-extraction-progress", {...})
    │
    ▼
useTasks.ts / SettingsModal.tsx 监听 progress 事件
    │
    ├─ 更新进度条、百分比、预估时间
    ├─ 暂停/恢复 → 调用 android_pause/resume_color_extraction
    └─ 取消 → 调用 android_cancel_color_extraction
```

## 二、Rust 后端实现

### 2.1 全局控制标志

**文件**: `src-tauri/src/lib.rs`

```rust
#[cfg(target_os = "android")]
static ANDROID_COLOR_PAUSED: std::sync::atomic::AtomicBool =
    std::sync::atomic::AtomicBool::new(false);

#[cfg(target_os = "android")]
static ANDROID_COLOR_CANCELLED: std::sync::atomic::AtomicBool =
    std::sync::atomic::AtomicBool::new(false);
```

使用 `AtomicBool` + `Ordering::SeqCst` 实现线程安全的暂停/取消控制，无需加锁。

### 2.2 暂停/恢复/取消命令

```rust
// 暂停：设置 PAUSED=true
fn android_pause_color_extraction() -> bool {
    ANDROID_COLOR_PAUSED.store(true, Ordering::SeqCst);
    true
}

// 恢复：重置 PAUSED=false, CANCELLED=false
fn android_resume_color_extraction() -> bool {
    ANDROID_COLOR_PAUSED.store(false, Ordering::SeqCst);
    ANDROID_COLOR_CANCELLED.store(false, Ordering::SeqCst);
    true
}

// 取消：设置 CANCELLED=true, PAUSED=false（解除暂停让循环继续到检查点）
fn android_cancel_color_extraction() -> bool {
    ANDROID_COLOR_CANCELLED.store(true, Ordering::SeqCst);
    ANDROID_COLOR_PAUSED.store(false, Ordering::SeqCst);
    true
}
```

关键设计：取消时同时解除暂停，否则暂停中的循环无法到达取消检查点。

### 2.3 单文件提取：`android_get_dominant_colors`

流程：

1. **查数据库缓存**：从 `color_db` 查询是否已有提取结果
2. **获取缩略图**：
   - 先检查缩略图缓存（`android::check_thumbnail_cache`）
   - 无缓存则调用 Kotlin 的 `generateThumbnail`（通过 JNI）
   - Kotlin 失败则回退到 Rust 的 `android::generate_thumbnail`
3. **提取颜色**：用 `image::open` 打开缩略图，调用 `color_extractor::get_dominant_colors` 提取8个主色调
4. **保存结果**：写入数据库

### 2.4 批量提取：`android_batch_extract_colors`

流程：

1. 重置 `ANDROID_COLOR_PAUSED` 和 `ANDROID_COLOR_CANCELLED`
2. 将所有文件路径添加到数据库 pending 表
3. 在 `spawn_blocking` 中逐个处理：
   - 检查 `ANDROID_COLOR_CANCELLED`，若为 true 则发送 `cancelled` 事件并返回
   - 检查 `ANDROID_COLOR_PAUSED`，若为 true 则循环等待（200ms 间隔）
   - 获取缩略图（缓存 → Kotlin → Rust 回退）
   - 提取颜色并保存到数据库
   - 通过 `app.emit("color-extraction-progress", ...)` 发送进度事件

进度事件结构：

```rust
{
    batchId: number,
    current: number,
    total: number,
    pending: number,
    currentFile: string,
    batchCompleted: boolean,
    cancelled?: boolean    // Android 独有字段
}
```

### 2.5 Kotlin JNI 缩略图生成

**文件**: `src-tauri/gen/android/app/src/main/java/com/aurora/gallery/MainActivity.kt`

Rust 通过 JNI 调用 Kotlin 的 `generateThumbnail` 方法：

```rust
fn call_kotlin_generate_thumbnail(file_path: &str, cache_dir: &str) -> Result<Option<String>, String> {
    let activity = ndk_context::android_context();
    let vm = unsafe { jni::JavaVM::from_raw(activity.vm().cast()) }?;
    let mut env = vm.attach_current_thread()?;
    let activity_obj = unsafe { jni::objects::JObject::from_raw(activity.context().cast()) };
    let json_result = env.call_method(&activity_obj, "generateThumbnail",
        "(Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;", ...)?;
    // 解析 JSON 返回 thumbnailPath
}
```

Kotlin 端的 `generateThumbnailInternal` 核心逻辑：

- 使用 `Semaphore(2)` 限制并发，防止内存溢出
- 缓存 key 使用 `文件大小-修改时间-路径hash` 的 MD5 哈希
- 支持 alpha 通道（PNG/WebP/GIF 保存为 WebP，其他保存为 JPEG）
- 目标缩略图尺寸 256px，压缩质量 85%

### 2.6 Rust 回退缩略图生成

**文件**: `src-tauri/src/android/thumbnail.rs`

当 Kotlin JNI 调用失败时的回退方案：

- `check_thumbnail_cache`：检查缩略图缓存是否存在
- `generate_thumbnail`：Rust 实现的缩略图生成（使用 `fast_image_resize` 和 `image` crate）
- `get_android_system_thumbnail`：通过 JNI 调用 Android 系统 `MediaStore.Images.Thumbnails.getThumbnail`

## 三、前端桥接层

**文件**: `src/api/tauri-bridge.ts`

所有 Android 颜色提取桥接函数通过 `isAndroidPlatformCached()` 判断平台，Android 端调用 `android_*` 命令，桌面端调用标准命令。

### 3.1 `getDominantColors`

```typescript
export const getDominantColors = async (filePath: string, count: number = 8, thumbnailPath?: string) => {
  if (isAndroidPlatformCached()) {
    const cacheRoot = _globalCacheRoot || '';
    const result = await invoke('android_get_dominant_colors', { filePath, count, cacheRoot });
    return result as DominantColor[];
  }
  // 桌面端：调用 get_dominant_colors，使用 thumbnailPath
  const result = await invoke('get_dominant_colors', { filePath, count, thumbnailPath });
  return result as DominantColor[];
};
```

关键区别：Android 端使用 `cacheRoot` 参数（Rust 层自行查找/生成缩略图），桌面端使用 `thumbnailPath`。

### 3.2 `pauseColorExtraction` / `resumeColorExtraction` / `cancelColorExtraction`

```typescript
export const pauseColorExtraction = async (): Promise<boolean> => {
  if (isAndroidPlatformCached()) {
    return await invoke<boolean>('android_pause_color_extraction');
  }
  return await invoke<boolean>('pause_color_extraction');
};

export const resumeColorExtraction = async (): Promise<boolean> => {
  if (isAndroidPlatformCached()) {
    return await invoke<boolean>('android_resume_color_extraction');
  }
  return await invoke<boolean>('resume_color_extraction');
};

export const cancelColorExtraction = async (): Promise<boolean> => {
  if (isAndroidPlatformCached()) {
    return await invoke<boolean>('android_cancel_color_extraction');
  }
  return true; // 桌面端无取消功能
};
```

注意：`cancelColorExtraction` 是 Android 独有功能，桌面端直接返回 true。

### 3.3 `androidBatchExtractColors`

```typescript
export const androidBatchExtractColors = async (filePaths: string[], cacheRoot: string): Promise<number> => {
  if (!isAndroidPlatformCached()) return 0;
  const result = await invoke<number>('android_batch_extract_colors', { filePaths, cacheRoot });
  return result;
};
```

Android 独有函数，桌面端使用 `addPendingFilesToDb` + `resumeColorExtraction` 的组合。

## 五、任务管理

**文件**: `src/hooks/useTasks.ts`

### 5.1 任务创建与跟踪

```typescript
const colorTaskIdRef = useRef<string | null>(null);
const colorBatchIdRef = useRef<number>(-1);
```

- `colorTaskIdRef`：当前颜色任务的 ID
- `colorBatchIdRef`：当前批次的 ID，用于检测新批次

### 5.2 进度事件处理

```typescript
await listen('color-extraction-progress', (event: any) => {
    const progress = event.payload;

    // 新批次检测 → 创建任务
    if (progress.batchId !== colorBatchIdRef.current) {
        colorBatchIdRef.current = progress.batchId;
        const taskId = startTask('color', [], t('tasks.processingColors'), false);
        colorTaskIdRef.current = taskId;
    }

    // 进度更新 → 计算预估时间
    updateTask(taskId, { current, total, currentFile, estimatedTime });

    // 批次完成
    if (progress.batchCompleted) {
        if (progress.cancelled) {
            // 取消：直接移除任务
            setState(prev => ({ ...prev, tasks: prev.tasks.filter(t => t.id !== currentTaskId) }));
            colorBatchIdRef.current = -1;
        } else {
            // 正常完成：标记完成，1秒后移除
            updateTask(taskId, { status: 'completed' });
            setTimeout(() => { /* 移除任务 */ }, 1000);
            colorBatchIdRef.current = -1;
        }
    }
});
```

关键：`colorBatchIdRef` 在批次完成或取消后重置为 -1，确保新任务创建新的 UI 条目。

## 七、颜色提取算法

**文件**: `src-tauri/src/color_extractor.rs`

Android 和桌面端共享同一套颜色提取算法 `get_dominant_colors`：

1. 转为 RGBA8，过滤透明像素和接近白色的像素
2. 使用 `color_thief` 提取调色板（quality=10，请求 count+8 个颜色）
3. 按频率权重(0.7) + 饱和度权重(0.3) 综合评分排序
4. 使用 CIE76 Lab 距离（阈值10.0）去重，确保颜色多样性
5. 最终按像素数量统计排序

## 十、系统通知栏

### 10.1 概述

在 Android 端进行批量主色调提取时，通过系统通知栏显示任务进度，用户可以在下拉通知中心查看进度、暂停/恢复或停止任务，无需切换到应用界面。

通知栏显示内容包括：
- 任务名称（"主色调提取"）
- 进度条与百分比
- 状态文本（进行中显示百分比，暂停显示"已暂停"）
- 暂停/恢复按钮、停止按钮
- 颜色色板图标

进度条颜色随状态切换：进行中为蓝色（#3B82F6），暂停为黄色（#EAB308）。

### 10.2 架构与通信流程

```
Rust (spawn_blocking)
    │
    ├─ call_kotlin_show_notification()  ──JNI──►  MainActivity.showExtractionNotification()
    │                                                   │
    │                                                   └─► startForegroundService(ColorExtractionService)
    │
    ├─ call_kotlin_update_notification() ──JNI──►  MainActivity.updateExtractionNotification()
    │                                                   │
    │                                                   └─► ColorExtractionService.updateProgress() + notifyUpdate()
    │
    └─ call_kotlin_hide_notification()  ──JNI──►  MainActivity.hideExtractionNotification()

    ColorExtractionService.onStartCommand()
        │
        ├─ ACTION_PAUSE  → nativePauseColorExtraction()  ──JNI──►  Rust 全局标志 + emit 事件
```

### 10.3 ColorExtractionService（前台服务）

**文件**: `src-tauri/gen/android/app/src/main/java/com/aurora/gallery/ColorExtractionService.kt`

`ColorExtractionService` 是一个 Android Foreground Service，使用 `dataSync` 类型（API 34+）。所有核心状态和方法都在 `companion object` 中，使 `MainActivity` 可直接调用。

**核心状态**：

```kotlin
companion object {
    var isPaused = false        // 暂停状态
    var currentTitle = ""       // 任务名称
    var currentProgress = 0     // 当前进度
    var currentTotal = 0        // 总进度
}
```

**通知构建（buildNotification）**：

```kotlin
fun buildNotification(context: Context): Notification {
    val accentColor = if (isPaused) COLOR_PAUSED else COLOR_RUNNING  // 黄色/蓝色

    val builder = NotificationCompat.Builder(context, CHANNEL_ID)
        .setSmallIcon(R.drawable.ic_color_palette)  // 颜色色板图标
        .setColor(accentColor)
        .setContentTitle(currentTitle)
        .setContentText(if (isPaused) "已暂停" else "$percent%")
        .setProgress(currentTotal, currentProgress, false)
        .setOngoing(true)
        .setOnlyAlertOnce(true)

    // 暂停时显示"恢复"按钮，进行中显示"暂停"按钮
    if (isPaused) {
        builder.addAction(ic_media_play, "恢复", pauseResumePending)
    } else {
        builder.addAction(ic_media_pause, "暂停", pauseResumePending)
    }
    builder.addAction(ic_menu_close_clear_cancel, "停止", stopPending)
}
```

**防抖机制（notifyUpdate）**：

Rust 后台循环和 `onStartCommand` 可能在短时间内多次调用 `notifyUpdate`，导致 Android 通知系统被频繁的 `notify()` 调用淹没。通过防抖机制确保短时间内只有最后一次更新真正生效：

```kotlin
private val mainHandler = Handler(Looper.getMainLooper())
private var pendingNotifyRunnable: Runnable? = null

fun notifyUpdate(context: Context) {
    if (isMainThread) {
        pendingNotifyRunnable?.let { mainHandler.removeCallbacks(it) }  // 取消之前的
        val runnable = Runnable {
            pendingNotifyRunnable = null
            manager.cancel(NOTIFICATION_ID)   // 先移除旧通知，强制重建 UI
            manager.notify(NOTIFICATION_ID, notification)
        }
        pendingNotifyRunnable = runnable
        mainHandler.postDelayed(runnable, 150)  // 150ms 延迟
    }
}
```

关键设计点：
- `removeCallbacks` 取消之前的待执行 Runnable，保证只有最后一次调用生效
- `cancel()` + `notify()` 强制 Android 完全重建通知 UI，确保 `setColor()` 的进度条颜色能正确切换
- 150ms 延迟窗口足够容纳连续的多次调用

**Intent 处理（onStartCommand）**：

```kotlin
override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
    when (intent?.action) {
        ACTION_START  -> startForegroundNotification()
        ACTION_PAUSE  -> { isPaused = true;  nativePauseColorExtraction();  notifyUpdate(this) }
        ACTION_RESUME -> { isPaused = false; nativeResumeColorExtraction(); notifyUpdate(this) }
        ACTION_STOP   -> { nativeCancelColorExtraction(); stopForeground(); stopSelf() }
    }
    return START_NOT_STICKY
}
```

### 10.4 JNI 桥接（Kotlin → Rust）

### 10.5 Rust → Kotlin 桥接

Rust 通过 JNI 调用 `MainActivity` 的三个方法：


### 10.6 Tauri 命令（供前端调用）

```rust
#[tauri::command]
async fn android_show_task_notification(app: AppHandle, title: String, current: i32, total: i32) {
    let _ = ANDROID_APP_HANDLE.set(app);  // 存储 AppHandle 供 JNI 使用
    spawn_blocking(|| call_kotlin_show_notification(...)).await
}

#[tauri::command]
async fn android_update_task_notification(current: i32, total: i32, is_paused: bool) {
    spawn_blocking(|| call_kotlin_update_notification(...)).await
}

#[tauri::command]
async fn android_hide_task_notification() {
    spawn_blocking(|| call_kotlin_hide_notification()).await
}
```

### 10.7 批量提取中的通知集成

在 `android_batch_extract_colors` 的 `spawn_blocking` 循环中：

```rust
// 任务开始时显示通知
let _ = call_kotlin_show_notification("主色调提取", 0, total_for_progress as i32);

for (idx, file_path) in file_paths.iter().enumerate() {
    // 暂停检测 → 更新通知为暂停状态
    if ANDROID_COLOR_PAUSED.load(Ordering::SeqCst) {
        let _ = call_kotlin_update_notification(idx as i32, total as i32, true);
        while ANDROID_COLOR_PAUSED.load(Ordering::SeqCst) { /* 等待恢复 */ }
    }
    // 进度更新 → 更新通知进度
    let _ = call_kotlin_update_notification(idx as i32, total as i32, false);
}

// 完成/取消时隐藏通知
let _ = call_kotlin_hide_notification();
```

### 10.8 前端事件同步

**文件**: `src/hooks/useTasks.ts`

前端监听 `color-extraction-notification-action` 事件，同步应用内 UI：

```typescript
useEffect(() => {
    const unlisten = await listen('color-extraction-notification-action', (event) => {
        const { action } = event.payload;
        if (action === 'pause') {
            setIsColorExtractionPaused(true);
        } else if (action === 'resume') {
            setIsColorExtractionPaused(false);
        } else if (action === 'cancel') {
            cancelColorExtraction();
        }
    });
}, []);
```

**文件**: `src/components/SettingsModal.tsx` / `src/App.tsx`

前端暂停/恢复操作同时更新通知栏状态：

```typescript
// SettingsModal 暂停时
await pauseColorExtraction();
await androidUpdateTaskNotification(current, total, true);

// App.tsx onPauseResume 时
await androidUpdateTaskNotification(current, total, isPaused);
```
