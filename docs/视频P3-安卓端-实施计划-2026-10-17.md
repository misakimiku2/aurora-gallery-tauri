## 0. 摸底结论（2026-10-17 现场核实，每条可复核）

安卓端视频率是**结构性的零**，与 `file_type` 判断无关：

| 事实 | 证据 |
|---|---|
| 扫描查的是 MediaStore 的**图片**集合，视频物理上不在里面（总文档 §2.7 根因二·口径 I，111 处） | `GalleryViewModelSequences.kt:245-305` 总入口、`GalleryViewModel.kt:753-757` 观察者只注册 `Images.Media.EXTERNAL_CONTENT_URI` |
| 网格/查看器共用的数据模型 `uniffi.aurora_core.Image` **没有任何类型字段** | `core/src/ffi.rs:119-138`（P3-A1 前）；`GridItem.Photo(image)` / `NativeGalleryView.ImageItem` 也无 Video 变体 |
| 查看器里**没有任何非图片分支**（pdf/psd/文件夹都没有） | `viewer/` 全包；唯一格式相关常量 `ImageSource.kt:49 ANIMATED_FORMATS` **无消费方** |
| 全仓无播放器：`ExoPlayer` / `MediaPlayer` / `VideoView` / `MediaMetadataRetriever` 零命中 | `grep kotlin-app/` |
| LAN 客户端**主动**过滤视频：四处代码 | `GalleryViewModelLanBrowse.kt:149/:452`、`GalleryViewModelLanAi.kt:357`、`LanFolderPickerDialog.kt:192`（189-191 是注释） |
| 读侧 SQL 早已放开 `IN ('Image','Video')`，**写侧硬编码 `file_type: "Image"`** —— 读通路开着、写通路堵着 | `core/src/ffi.rs:449`（快照）/ `:499`（增量） |
| `MediaThumbnail.kt` 是死代码（零调用点），改安卓网格时别去动它 | 全仓 grep 无引用 |

**开工前置发现（不在原计划里，但必须排在前面）**：10-16 那次给 `file_index` 加
`video_codec` / `bit_rate` 两列（`2938f1509`）时，core 的 `cargo test --lib` 编译被取消、
只做了人工核对，实际漏了 4 处 —— 三个只读函数的 SELECT 停在 14 列而行映射读
`get(14)/(15)`（调用即 `InvalidColumnIndex(14)`），以及 `reconcile_mediastore_snapshot`
（**安卓扫描写入路径**）的 INSERT 也停在 14 列。桌面端今天没暴露，是因为装机用的
`libaurora_core.so` 是 10-12 编的（14 列时代，自洽）——**这条雷会在安卓 P3 重编 so 的那一刻引爆**，
所以先修再编（`1c195ec4c`）。

## 2. 对总文档 §5.5「七条缺口」的逐条核对（**两条其实不用做**）

| # | 缺口 | 核对结果 |
|---|---|---|
| 1 | 播放器（引入 ExoPlayer） | ⬜ **仍缺**，A2 做 |
| 2 | 服务端 Range | ✅ **已完成**（从 P3 提前到 P1 那轮）：`handle_image → serve_file_with_range`，`handlers.rs:1690-1720`，206 有单测 |
| 3 | 放开四处代码过滤 | ✅ A1 完成（头像候选那处按「举证例外」保留，见 §3） |
| 4 | **视频缩略图需服务端提供封面帧** | ✅ **不需要做**。`handle_thumbnail → get_thumbnail → process_single_thumbnail` 早有视频分支（缓存命中 / ffmpeg 抽帧，`thumbnail.rs:163-178`）。实机核对：`/api/thumbnail` 对 `.mp4` 回 `200 image/jpeg`，JPEG 注释带 `Lavc63.1.102`。总文档那句「视频没有缩略图端点」指的是 `BrowseItem.thumbnail` 字段被置 None，而安卓端 `lanImageOf` 自己按 path 拼 URL、**根本不读该字段** —— 是表述陈旧，不是能力缺失 |
| 5 | MIME `video/*` | ✅ 已完成（P0/P1 那轮） |
| 6 | 口径 E + 类型转换点 | ✅ 桌面侧 P1 已完成；安卓侧的类型真源问题以 `Image.file_type` 解决（A1） |
| 7 | 口径 I · MediaStore 111 处 | ⬜ **未做** —— 属「本地库」那一半（B 线），LAN 这条路完全不碰它 |

**新发现的第八条缺口（总文档没有）**：browse/search 的**索引分支只认 `Image`**，而
`get_children_by_parent_path` 的 WHERE 从视频 P1 起就含 `'Video'` → 索引里的视频行被静默丢掉，
再由 FS 补扫以「无宽高」的形态加回来，客户端因此把 3440×1440 的录屏排成 1:1；且协议里
**根本没有时长字段**，视频卡片与图片卡片视觉无差别。→ A3（服务端）+ A4（角标）修掉。

## 4. 构建链与本机环境（两台机共用仓库，这些不进代码）

**改 `core/src/ffi.rs` 的结构体＝必须走全链**（M1 §7 行 364 已记，此处补模拟器相关两条）：

```
cargo build（host dll，落 C:/cargo-target-core）
→ cargo run --bin uniffi-bindgen -- generate --library …/aurora_core.dll --language kotlin \
    --out-dir ../kotlin-app/app/src/main/java
→ cargo ndk -t arm64-v8a -t x86_64 -o …/jniLibs build --release   # 只编 arm64 模拟器缺符号必崩
→ gradlew :app:installDebug
```

- **本机（.165）仓库路径含中文**，AGP 在 apply plugin 阶段硬失败「project path contains
  non-ASCII characters」。绕过 = 挂 ASCII 盘符，**不改仓库配置**（`gradle.properties` 两台机共用，
  不该为单机加 `overridePathCheck`）：
  `cmd //c "subst A: E:\桌面备份\git"` → 从 `A:/aurora-gallery-tauri/kotlin-app` 编译 →
  用完 `subst A: /D`。
- `adb` 不在 bash 的 PATH，用全路径 `E:/Android/Sdk/platform-tools/adb.exe`。
- AVD 必须建在**默认位置**（`C:\Users\misak\.android\avd`）才看得见；老的 `proof_avd` 在
  `E:\Android\.android`（`ANDROID_USER_HOME`），android-emulator 插件列不出它。
- `scripts/kotlin-dev.ps1` 只编 arm64-v8a，模拟器路线要手动补 x86_64。
- **`| tail` 会把退出码吞成 0**：本轮 `cargo test` 与一次 `cargo ndk` 都被这个假绿骗过，
  必须 `${PIPESTATUS[0]}` 或直接看 `test result:` 行。

## 6. 覆盖度如实登记（**验过 ≠ 全验过**）

- **模拟器 ≠ 真机**：硬件解码器行为、`HEVC` 是否有解码器、大文件 seek 流畅度、控件手感，
  模拟器结论一律不作终验依据。A2 完成后需上平板/手机复验。
- **捏合三档布局在模拟器上验不了**：roadmap V4 早已登记「模拟器合成输入无法稳定触发双指」。
  瀑布流/自适应下的视频卡片比例，本轮是验收人在自己截图里补证的，不是我拍的。
- **A3 的服务端改动只在 .189 那一个库上验过**：未覆盖「目录压根没被索引」的纯 FS 回退分支
  （代码路径写了、没实机走到）。也没覆盖 mkv/avi 在 LAN 下的封面（样本里两个 mkv/avi 是
  转封装产物，已验到同名 mp4 的封面，容器本身待 A2 播的时候一起看）。
- 桌面端 P2 仍欠两条实机尾巴（设置面板缓存清理、移走 ffmpeg 的降级演练），与本文无关，
  记在 `docs/视频P2-播放格式兜底-实施计划-2026-10-15.md` §6。
