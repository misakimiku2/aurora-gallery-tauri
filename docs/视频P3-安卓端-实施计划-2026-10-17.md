## 0. 摸底结论（2026-10-17 现场核实，每条可复核）

安卓端视频率是**结构性的零**，与 `file_type` 判断无关：

| 事实 | 证据 |
|---|---|
| 扫描查的是 MediaStore 的**图片**集合，视频物理上不在里面（总文档 §2.7 根因二·口径 I，111 处） | `GalleryViewModelSequences.kt:245-305` 总入口、`GalleryViewModel.kt:753-757` 观察者只注册 `Images.Media.EXTERNAL_CONTENT_URI` |
| 网格/查看器共用的数据模型 `uniffi.aurora_core.Image` **没有任何类型字段** | `core/src/ffi.rs:119-138`（P3-A1 前）；`GridItem.Photo(image)` / `NativeGalleryView.ImageItem` 也无 Video 变体 |
| 查看器里**没有任何非图片分支**（pdf/psd/文件夹都没有） | `viewer/` 全包；唯一格式相关常量 `ImageSource.kt:49 ANIMATED_FORMATS` **无消费方** |
| 全仓无播放器：`ExoPlayer` / `MediaPlayer` / `VideoView` / `MediaMetadataRetriever` 零命中 | `grep kotlin-app/` |

### 5.5 影院态接管窗口 chrome（`042355d4d`）

**与那条旧账不冲突的关键**：B2 禁的是对导航栏做 **hide/show**（MagicOS 留色带的成因是
「insets 隐藏→重新显示」那个事件源，不是色值本身），而 `applyWindowTheme` 常态本来就在写
`navigationBarColor`（2026-10-07 EMUI 手势栏报障时加的）。这一轮**只写色、不动任何 insets
的显隐**，用的是同一个属性的同一写法。

- 查看器只发信号：`onStageChromeChange(Boolean)`（`onImmersiveBarsChange` 同款形制），
  色值一律写在宿主 `applyViewerStageChrome`：黑档刷 window background + `statusBarColor` +
  `navigationBarColor` + 状态栏图标转白；还原**交回 `applyWindowTheme` 那唯一出处**，
  不自己拼色值（§5.4 那条「第二处写背景」的坑刚踩过）。
- **按状态去重发送**：`applyChromeColors` 每次换页都跑，不去重就会每页写一遍窗口属性。
- 沉浸态正在接管时（`viewerBarsHidden`）本函数直接让位，不跟它抢。
- `close()` 里**显式** `emitStageChrome(false)`：那时序列还在，按 `isVideoStage()` 判仍会
  判成视频态，靠判定还原不了。

实测（模拟器）：进视频 = 状态栏与手势区整条转黑、图标转白 ✅；翻回图片项 = 立刻还原浅色 ✅；
在视频上退出查看器 = 网格的浅色 chrome 回来 ✅。
**真机待复验**：MagicOS/EMUI 上这条色带只有 V1/V2 那份逐像素账，本轮没在真机上验过。

### 5.6 自动全屏 + 捏合两处（验收人第五轮，2026-10-17）

1. **绑上视频即自动全屏**（验收人：「播放视频后应该会自动进入全屏」）。走的是沉浸态那条
   现成接管链（宿主 `setViewerImmersiveBars`：藏状态栏 + 窗口色置黑 + 还原时先涂主题色再 show），
   查看器只发 `emitStageFullscreen(stage)` 信号。四条要点：
   - **它是第三个来源，不复用 `isImmersive`**：影院态由「当前项是视频」推出来，不是用户按出来的，
     写进 isImmersive 会把「单击切换、退出还原」那整套语义搅进来；新加 `videoStageHidesBars`。
   - 它同时进 **`isChromeHidden()`** 那张门（原本只有 isImmersive / 幻灯片两项）。
     漏掉的症状正是 B2 当年为图片沉浸态修过的那个：藏栏那一帧 `syncStatusBarInset` 读到
     insets=0，把顶栏的状态栏让位量改没 → 顶栏往上跳一整个状态栏。
   - `close()` 里**不走** emit 那条「isImmersive 时不抢」的早退（退出查看器时 isImmersive
     可能还没落 false），直接清标志位并显式 `onImmersiveBarsChange(false)`。
   - 回前台重申：`MainActivity.onResume` 那条原本只认 `isImmersiveNow()`，现在也认影院态
     （切后台时系统会把状态栏放回来）。
2. **捏合只能放不能缩**：`userScale` 下限当初写成 `1f`，等于把「缩小」这个动作整个吃掉。
   放开到 `0.3f`，并在 `onScaleEnd` 把接近基准位的值（±0.06）吸附回 `1f`，免得停在 1.03
   这种既不是原样也看不出差别的位置。
3. **捏合时误触亮度/音量**：根因是「先落一指、略微移动再补第二指」这个最常见起手式——
   第二指落地前那一下 `ACTION_MOVE` 只有 1 个指针、`scaleDetector.isInProgress` 还是 false，
   于是被单轴判定认成了竖滑。改成 `ACTION_MOVE` 只要 `pointerCount > 1` 就 `cancelDrag()`，
   并在 `onScaleBegin` 里也撤一次（进度拖拽交回 ticker；亮度/音量已改的不回滚）。

实测：进视频 = 状态栏消失、画面区随之变高（封面按新的媒体区重铺）✅；
翻回图片项 = 状态栏立刻回来 ✅；在视频上按返回退出查看器 = 网格状态栏回来 ✅。

### 5.7 倍速档（第六轮，`3038307d7`）

4. **真源是本层的 `speedIdx` 字段**，每次 `start()` 重新下发一次 `PlaybackParameters`，

6. 留一行 `Log.d(TAG, "倍速 -> …")`：播放器速率这件事 UI 层级读不出来（`uiautomator` 里没有

## 6. 覆盖度如实登记（**验过 ≠ 全验过**）

- **模拟器 ≠ 真机**：硬件解码器行为、`HEVC` 是否有解码器、大文件 seek 流畅度、控件手感，
  模拟器结论一律不作终验依据。**A2 实测就是这条的现场版**：样本是 3440×1440@60，模拟器只有
  `c2.goldfish.h264.decoder` 软解，日志直接报 `NoSupport [sizeAndRate.cover, 3440x1440@59.97]`
  → 播得动、出画、进度在走，但**速度追不上实时**（8 秒墙钟走 2 秒片），中央转圈常驻。
  所以「能不能播 / 交互语义 / 音频焦点」这几条算验过了，**流畅度与手感不算**，需上平板/手机复验。
- **捏合三档布局在模拟器上验不了**：roadmap V4 早已登记「模拟器合成输入无法稳定触发双指」。
  瀑布流/自适应下的视频卡片比例，本轮是验收人在自己截图里补证的，不是我拍的。
- **A3 的服务端改动只在 .189 那一个库上验过**：未覆盖「目录压根没被索引」的纯 FS 回退分支
  （代码路径写了、没实机走到）。
- ✅ 原记在上一行的尾巴「mkv/avi 在 LAN 下的封面与容器本身待 A2 一起看」——**A2 已销**：
  两种转封装产物的封面角标、抽屉预览、以及播放出画全部实测通过（§5.1）。
- **A2 没验到的**：幻灯片里混入视频（只改了取图源，没实机跑一轮放映）、删除/移动当前这条视频
  后的序列衔接（走 `loadCurrent` → `syncVideoLayer` 同一条路，逻辑上通，没实测）、
  断线中途正在播放（LAN 掉线时 ExoPlayer 报 `PlaybackException` → Toast + 退回静态位，
  错误码文案没做过人工校对）。
- **A2.5 没验到的三条**：
  ① **双指捏合缩放**——roadmap V4 早登记的旧账，模拟器合成双指不可靠，这轮**一行没验**，
  真机必测；第五轮那两条修正（下限放开到 0.3、多指撤销单轴判定，§5.6）同样
  **只改了代码、没在模拟器上验**；② **亮度手势的实际效果**——浮层与 `screenBrightness` 赋值路径都走到了，
  但模拟器 `dumpsys window` 里取不到该字段，背光有没有真变没取证；
  ③ **循环真的重播**——只验到开关位与图标染主色，`REPEAT_MODE_ONE` 的自动重播
  被模拟器解码速度拖住没等到片尾第二轮。
- **倍速只验到「钮与下发」，没验到「速率真的变了」**（§5.7 三条未取证）：模拟器软解本就追不上
  实时，媒体时间推进被解码吞吐钳住，1x 与 2x 读不出差别；音调只有字节码结论、没实听。真机必测。
- **A2.5 换来的一条取舍（不是遗漏，是拍板）**：视频层现在吃掉画面区触摸，于是
  **播放中不能横滑翻页、不能竖滑拉抽屉**（改走上一条/下一条键与顶栏信息钮）。
  静态位保留横滑翻页。这条与图片的手感断裂，真机上若被反馈「翻不动」，
  解法是给视频补一个左右边缘的翻页热区，而不是回退手势表。
- 桌面端 P2 仍欠两条实机尾巴（设置面板缓存清理、移走 ffmpeg 的降级演练），与本文无关，
  记在 `docs/视频P2-播放格式兜底-实施计划-2026-10-15.md` §6。
