# 人物栏性能优化与头像锯齿问题修复尝试

## 问题描述

当左侧人物栏展开时（42个人物），中间的文件界面在滚动页面时会出现明显的卡顿和掉帧现象。收起人物栏后问题消失。同时，人物默认头像（用户设置的图片头像）存在锯齿问题，而手动设置的头像则有抗锯齿效果。

## 问题分析

### 滚动卡顿原因

1. **渲染负担**：42个人物卡片在展开时全部渲染，每个卡片包含图片元素
2. **合成层竞争**：人物栏的图片与主文件区域的缩略图竞争 GPU 合成层资源
3. **重绘传播**：主区域滚动时，侧边栏元素可能触发级联重绘
4. **图片解码**：展开状态下会加载和解码多张图片

### 头像锯齿原因

1. **图片缩放**：头像容器为 40px，图片需要缩放显示
2. **缺少 GPU 加速**：容器没有应用 `transform: translateZ(0)` 等属性
3. **渲染隔离不足**：没有创建独立的层叠上下文

## 尝试的修复方案

### 1. GPU 加速优化

为头像容器和图片添加 GPU 加速属性：

```tsx
// TreeSidebar.tsx 和 PersonGrid.tsx
<div style={{ 
  transform: 'translateZ(0)', 
  backfaceVisibility: 'hidden', 
  isolation: 'isolate' 
}}>
  <img style={{ transform: 'translateZ(0)' }} />
</div>
```

### 2. CSS Containment 隔离

为侧边栏和人物区域添加 CSS containment：

```tsx
// 整个侧边栏
<div style={{ contain: 'layout style paint' }}>

// PeopleSection 组件
<div style={{ contain: 'layout style' }}>
```

### 3. 图片懒加载

为人物头像图片添加懒加载属性：

```tsx
<img loading="lazy" decoding="async" />
```

### 4. 默认图标优化

调整默认 User 图标的尺寸和描边：

```tsx
<User size={18} strokeWidth={1.5} />
```

## 测试结果

**修复效果：无效**

- 锯齿效果依然存在
- 滚动性能没有实质性提升

## 可能的深层原因

### 滚动卡顿

1. **WebView2 渲染限制**：Tauri 使用 WebView2，可能存在与 Chrome 不同的渲染行为
2. **虚拟化不够激进**：当前虚拟化策略可能不足以处理大量图片元素
3. **主线程阻塞**：React 组件更新可能导致主线程阻塞
4. **内存压力**：42个图片同时存在可能造成内存压力

### 头像锯齿

1. **图片缩放算法**：浏览器/WebView2 的图片缩放算法可能不够优化
2. **原始图片分辨率**：如果原始图片分辨率较低，缩放后会出现锯齿
3. **CSS transform 缩放**：使用 transform 进行缩放可能比 width/height 更平滑

## 后续建议

### 滚动性能优化

1. **完全隐藏策略**：当鼠标不在侧边栏时，完全隐藏人物头像图片，只显示占位符
2. **Intersection Observer**：使用 Intersection Observer API 实现更精确的可见性检测
3. **Canvas 渲染**：考虑使用 Canvas 渲染人物头像，减少 DOM 节点
4. **Web Worker**：将图片解码放到 Web Worker 中

### 头像锯齿优化

1. **预生成缩略图**：在后端预生成头像缩略图，避免前端缩放
2. **CSS image-set**：使用 image-set 提供不同分辨率的图片
3. **SVG 滤镜**：尝试使用 SVG 滤镜进行平滑处理
4. **CSS image-rendering**：尝试不同的 image-rendering 值（auto、smooth、high-quality、crisp-edges、pixelated）
