> **桌面端播不了 AVI/WMV，是播放器内核能力问题，不是文件格式问题。**

  （等 100 秒、占 2 GB 等大副本，换来的还是黑屏）

## §2 目标架构（最终态）

```
桌面端本地播放
  ├─ Chromium 能解的编码（H.264/VP8/VP9/AV1…）→ WebView2 <video>（现状保留）
  └─ 其余一律 → libmpv 嵌入（popup 顶层窗口，跟随主窗口同步）  ← 播原文件，零转码

LAN 手机端播放
  ├─ 手机能解的容器 + 编码 → HTTP Range 直读原文件（现状 direct）
  └─ 其余 → 服务端 HLS 流式（EVENT 分片，不落全量、秒开、原生 seek）
```

**两条腿互不依赖**，可并行推进。

**最终收益**：
- 桌面端：`video_remux` 桌面端路径（remux 作业 / LRU / 4 GiB 预算 / 等待态 UI）**整体删除**
- LAN 端：从「等 102 秒」变成「约 1 秒起播」

### 任务清单

1. **判据从「容器」改为「编码」**
   - 桌面端维护一张「Chromium 能解的**编码**白名单」
   - 与既有的 `ANDROID_DECODABLE_CODECS` **口径并列不同源**（手机端是另一张表）
   - ⚠️ 编码字符串是 **revelo / MediaInfo 口径**（`MPEG-4 Visual` / `AVC` / `JPEG`…），
     **不是 ffmpeg 口径**；改表前拿真样本打印一遍，别照 ffmpeg 写法猜

2. **ImageViewer 接 mpv**
   - 不可原生解 → `poc_mpv_open(原文件路径, rect)`
   - **删除** `forceRemuxTriedRef` 那套 remux 兜底阶梯
   - 生命周期：切文件 / 关查看器 → `poc_mpv_stop`

3. **窗口跟随**
   - Rust 侧 Hook 主窗口 `WM_WINDOWPOSCHANGED`（覆盖移动与缩放）
   - 同步 popup 窗口位置与尺寸
   - ⚠️ popup 不随 owner 自动移动，必须手动同步

4. **最小控件**
   - `src/components/viewer/VideoControls.tsx` 改为驱动 mpv
   - 播放 / 暂停 / seek / 音量

**验收标准**

- `MDS-807.avi`（MPEG-4 Part 2）、`Tokyo Hot n0742-skp2p.com.wmv`（VC-1）点击即播
- 暂停 / 恢复、快进 60s 正常

- 切到图片 / 关查看器后，mpv 进程退出（任务管理器核对）

## §6 全局约定

1. **判定看编码，不看容器**（不同容器装同编码，结论不同）
2. **桌面端画面窗口必须 top-level popup**（`WS_CHILD` 必被 WebView2 覆盖，与 z-order 无关）
3. **运行时加载 dll，不链接导入库**（LGPL 合规 + msvc/MinGW 格式不匹配）
4. **本机跑 cargo 必须清代理环境变量**：
   `http_proxy= https_proxy= HTTP_PROXY= HTTPS_PROXY= cargo <cmd>`
   （端口会变，历史记录 7897 已过时，当前环境变量是 8819 且返回 502）
5. **改完 src-tauri 核心跑 `cargo test --lib` 收口**，别只跑 `cargo check`
