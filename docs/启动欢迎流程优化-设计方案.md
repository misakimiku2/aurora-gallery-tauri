# 启动欢迎流程优化（桌面 + 安卓）设计方案

> 2026-09-29 起草。状态：**待用户审阅**。
> 范围拍板：桌面端欢迎向导新增「AI 设置」「移动端互联」两步（均可选跳过）；安卓端从 0 到 1 建欢迎流程，步骤与桌面对齐。

## 1. 背景

### 桌面端现状（React + Tauri，src/）
- 欢迎向导 `src/components/modals/WelcomeModal.tsx`：两步全屏模态。第 1 步选图库文件夹（系统目录选择器 + 扫描进度，未选完「下一步」禁用）；第 2 步语言 + 主题（「跳过」按钮仅此步出现）。
- 触发：`src/hooks/useAppInit.ts:388`（无 user_data 历史时 `setShowWelcome(true)`）+ `src/App.tsx:507` 兜底（`aurora_onboarded` localStorage 标记 + `roots.length === 0`）。完成后不再出现，仅测试钩子 `window.showWelcomeModal` 可重开。
- 移动端互联能力已有：`settings.lanShare.androidClient`（手机扫码/手填连接桌面，桌面侧栏浏览/下载手机图片，见 `src/utils/translations.ts:716,767-792`）；二维码生成 `generateQRCodeUrl` 在 `src/components/settings/LanSharePanel.tsx` 内使用。AI 设置面板 `src/components/settings/AISettingsPanel.tsx`，连接测试走 `aiService.checkConnection`。

### 安卓端现状（原生 Kotlin，kotlin-app/，Compose + uniffi Rust core）
- **无任何欢迎流程**：`MainActivity.kt:1741` 在 `onCreate` 末尾直接 `requestMediaPermissionIfNeeded()`，系统权限弹窗冷启动裸弹，无铺垫。
- 拒绝权限无兜底：界面停在空网格（「文件夹为空」，`MainActivity.kt:2957-2968`），无重试/去设置引导。
- 可复用基建齐备：
  - 持久化 `state/AppSettings.kt` `SettingsStore`（SharedPreferences `aurora_settings`）：已有 language/theme/ai JSON 字段；**无首启标记**。
  - AI 配置：`AiSettings` + `toAiConfig()`；连接测试 UI 在 `ui/components/SettingsDialog.kt:568`（「测试连接」按钮，core 同步 FFI 走 IO 线程）。
  - 互联服务端：`LanServerManager.setEnabledOn(autoEnable: Boolean): Boolean`（起 HTTP + 前台服务，返回快照 ip/port/accessCode）；快照含 enabled/running/ip/port/accessCode/deviceCount。
  - 布局分档：`ui/FormFactor.kt` `isCompactWidth` / `isTabletForm`。
  - 权限链：`MainActivity.kt:181` `requestPermission` launcher（granted → `viewModel.startScanIfNeeded()`）、`requestMediaPermissionIfNeeded()`（1904）、通知权限（1892）。
  - i18n：res `values/strings.xml`（默认英文）+ `values-zh-rCN/strings.xml`；但主界面大量文案硬编码中文（如「文件夹为空」直接写在 Kotlin 里）。
- 单元测试基建薄弱：仅 `app/src/test/.../canvas/CanvasLogicTest.kt`；项目验收惯例为模拟器/三星平板实测。

## 2. 方案选型

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| **A. 两端各自原生实现** | 桌面在 WelcomeModal 内扩步；安卓新建 Compose 向导 `WelcomeFlow.kt`。各自复用既有数据层与服务 API，不建跨端抽象。 | **选定**。技术栈异构（React vs Compose），欢迎流程是一次性交互，抽象不值；M7 D42 已退役 Tauri-on-Android 路线，共享 web 层无承载。 |
| B. 共享 web 欢迎层 | 把向导做成 web 页面两端复用。 | 否决。安卓端是原生 Compose 应用，无 webview 承载；引入嵌套 webview 只为一个向导，得不偿失。 |
| C. 安卓极简单页 | 安卓只加一个权限说明页，不做完整向导。 | 否决。不满足「两端对齐」（桌面明确加 AI/互联两步）与权限拒绝兜底目标。 |

## 3. 桌面端设计（2 步 → 4 步）

### 3.1 步骤结构

| 步 | 内容 | 跳过 |
| --- | --- | --- |
| 1 选文件夹 | 现状不动（必须选完 + 扫完才能下一步） | 不可 |
| 2 语言 + 主题 | 现状不动 | 不可（原「跳过」按钮移除，见 3.2） |
| 3 AI 设置（新增） | 精简配置卡：provider 三选一（openai/ollama/lmstudio）+ endpoint/apiKey/model 输入 + 「测试连接」。数据经现有 `onUpdateSettings({ ai })` 落 settings.ai；测试复用 `aiService.checkConnection`。 | 可：显式「跳过，稍后在设置中配置」按钮，不写任何 ai 字段 |
| 4 移动端互联（新增，即需求所称「移动端下载」） | 说明双向互联价值（手机扫码连桌面 → 桌面侧栏浏览/**下载手机图片**；手机浏览器访问桌面图库）+ 内嵌开启卡：开关 → `lanShareStart`（现有 tauri-bridge 命令），成功后展示 IP/端口/访问码 + 二维码（复用 `generateQRCodeUrl`）。 | 可：「跳过，稍后在设置中开启」 |

- i18n：`src/utils/translations.ts` 新增 `welcome.ai*` / `welcome.mobile*` 中英键（现有中英键一致性 vitest 兜底防漏）。

### 3.2 导航与跳过规则
- 步骤指示器由 2 条扩为 4 条，保持可点回退；左侧品牌区标题/描述按步切换（沿用现有 `welcome.step1Title` 模式新增键）。
- 新增步（3、4）右下角提供「跳过」+「下一步/完成」；跳过 = 直接前进一步且不落盘。
- 原第 2 步的「跳过」按钮语义变化：向导尾步变为第 4 步，「完成」即 finish；第 2 步不再是尾步，其「跳过」移除（避免「跳过」后落到新步骤造成语义混乱）。
- 第 1 步「必须选完文件夹」约束**保持不变**（用户未选择放开）；`onFinish`（写 `aurora_onboarded` + 触发后台扫描）逻辑不变。

### 3.3 测试
- 新增 `src/components/modals/__tests__/WelcomeModal.spec.tsx`（vitest + testing-library，项目已有此模式）：
  1. 步 3 填写 → `onUpdateSettings` 收到 ai 更新；点跳过 → 不收到。
  2. 步 4 开启 → 收到 lanShare 更新；跳过 → 不收到。
  3. 指示器回退 / 下一步推进 / 尾步完成回调。
  4. 回归：步 1 未选文件夹时「下一步」禁用。
- 手动验收：首启 4 步全走 / 中途跳过 / 重启不再弹。

## 4. 安卓端设计（0 → 1）

### 4.1 新组件 `ui/components/WelcomeFlow.kt`
- 全屏 Compose 向导，取色走 `AuroraTheme.colors`；视觉母题对齐桌面 WelcomeModal：Aurora logo、噪点 + 点阵纹理背景、动态色斑（Compose 渐变/blur 简化实现）。
- 布局分档：手机竖屏上下结构（顶部品牌横幅 + 底部内容卡），平板横屏左右分栏对齐桌面（`FormFactor.isCompactWidth` / `isTabletForm` 分档，项目主测三星平板）。
- 步骤状态机抽为纯 Kotlin（`WelcomeFlowState`：当前步、推进/回退/跳过/完成判定），便于加 JUnit 测试（对齐 CanvasLogicTest 惯例）。

### 4.2 步骤（对齐桌面四步）

| 步 | 内容 | 行为 |
| --- | --- | --- |
| 1 权限 | logo + 「需要读取设备图片媒体库以展示照片」说明 + 「授权并继续」 | 复用现有 `requestPermission` launcher；**已授权则自动跳过本步**；拒绝后本步切换为兜底态：说明 + 「去系统设置授权」按钮（`ACTION_APPLICATION_DETAILS_SETTINGS`）——修复现状「拒绝即死在空网格」。授权成功即调 `viewModel.startScanIfNeeded()`（后台扫描，不阻塞向导继续） |
| 2 偏好 | 主题三档（浅色/深色/跟随系统）+ 语言两档（中文/English） | 写 `SettingsStore` 既有 theme/language 字段。**范围约束**：语言切换本次只保证欢迎页自身与 strings 资源覆盖文案（欢迎页文案按 `settings.language` 在组合内选中/英小字典，不做 per-app locale 重创建）；主界面全量 i18n 是既有另案，不在本设计内 |
| 3 AI 设置（可选） | provider + endpoint/apiKey/model + 「测试连接」（复用 SettingsDialog AI Section 同款 FFI 调用） | 落 `SettingsStore` ai JSON；「跳过，稍后在设置中配置」不落盘 |
| 4 互联（可选） | 说明 + 「开启局域网共享」→ `LanServerManager.setEnabledOn(true)`；成功后展示 IP/端口/访问码（桌面端扫码或手填连接后可在侧栏浏览/下载手机图片） | 「跳过，稍后在设置开启」不落盘 |
| 5 完成 | 「开始使用」 | 写 `SettingsStore` 新键 `onboarded=true` → 关向导进主界面 |

### 4.3 触发与升级兼容（MainActivity）

- `SettingsStore` 新增 `KEY_ONBOARDED`（boolean，缺省 false）。
- `onCreate` 中**替换**现有的无条件 `requestMediaPermissionIfNeeded()`（`MainActivity.kt:1741`）为：
  ```
  if (!prefs 有 onboarded 标记 && 媒体权限未授予) → 渲染 WelcomeFlow（首启新用户）
  else → 若缺标记则静默补写 onboarded=true；走现有 requestMediaPermissionIfNeeded()（行为与 2.0.0 完全一致）
  ```
- 升级兼容：2.0.0 老用户（已授权、无标记）零打扰——不弹向导、权限与扫描路径不变，仅静默补标记。
- 边界登记：`onboarded=true` 在向导**完成时**才写（对齐桌面 handleWelcomeFinish 时机）。首启用户在向导中途强杀进程后重启：权限已授予 → 判定不满足首启条件，直接进主界面（主题/语言/AI 停留默认值，可去设置补配），不重弹向导——接受此行为，不做中途持久化。
- 宿主接线：向导以全屏覆盖层渲染在主 `App` 之上（数据/扫描照常初始化，完成即揭幕，观感对齐桌面 splash → welcome）；AI 测试连接与互联开关经宿主回调走现有实例（`GalleryViewModel` / `LanServerManager`）。

### 4.4 i18n
- 欢迎页新增文案走 `res/values/strings.xml` + `values-zh-rCN/strings.xml` 双份 `welcome_*` 键；步内即时语言切换用组合内字典（见 4.2 步 2 约束）。

### 4.5 测试与验收
- 单元：`WelcomeFlowState` 步骤机 JUnit（推进/回退/跳过/完成/已授权跳过权限步判定）。
- 模拟器/平板实测（项目惯例）：
  1. 清数据首启 → 先见向导权限步（而非系统裸弹窗）；
  2. 授权 → 自动进偏好步，后台已开始扫描；
  3. 连跳 AI、互联两步 → 完成 → 主界面网格已有扫描结果；
  4. 杀进程重启 → 不再弹向导；
  5. 首启拒绝权限 → 兜底态出现 →「去系统设置」授权返回 → 正常进入；
  6. 覆盖安装 2.0.0 场景（已授权无标记）→ 不弹向导，行为与现版一致；
  7. 平板横屏 / 手机竖屏两档布局正确；
  8. AI 步填真实配置「测试连接」成功；互联步开启后桌面端可扫码连上并浏览手机图片。

## 5. 明确不做
- 桌面第 1 步放开「必须选文件夹」（用户未选此项）。
- 设置里「重跑欢迎向导」入口（两端均未要求）。
- 安卓主界面全量 i18n（硬编码中文文案治理，另案）。
- 欢迎页不做 AI 高级项（预设/视觉面板/任务开关明细）——只做连接必需的最小集，其余留在设置。

## 6. 实现切分建议
1. 桌面：WelcomeModal 扩步 + i18n + 组件测试（独立可发）。
2. 安卓：WelcomeFlowState 纯逻辑 + WelcomeFlow.kt + MainActivity 触发改造 + strings 双语键。
3. 联调验收：模拟器 + 平板全场景清单（4.5）跑一遍。
