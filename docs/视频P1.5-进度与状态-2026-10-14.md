## 2. 修掉的三处既有 bug（同一条命令上的连环雷）

`save_remote_thumbnail` 这条命令**自诞生起从未跑通过**（前端 AVIF 回落也走它，一直没生效）。

1. **嵌套结构传参字段名不匹配**：Rust `ColorResult` 是 snake_case（`lab_l / lab_a / lab_b / is_dark`，全非 Option），
   TS 传的是 `labL/labA/labB/isDark` → serde 报 missing field。修：`thumbnail.ts` 的 `toRustColors()`。
2. **state 类型不匹配**：命令里 `app.state::<ColorDbPool>()`，而 `lib.rs` 注册的是 `Arc<ColorDbPool>` →
   `state() called before manage()` panic。修：改为 `Arc<ColorDbPool>`。
3. **自死锁**：先 `pool.get_connection()` 拿住 `MutexGuard`，再调 `batch_save_colors`（它内部再次 lock 同一把锁，
   `ColorDbPool` 是单连接 `Arc<Mutex<Connection>>`）→ 同线程永久死锁，invoke 永不返回。修：调换顺序。
   附带：**颜色持久化失败不再拖垮封面**（降级为 `log::warn`），否则封面已落盘但 TS 拿不到路径 → 每次挂载重抽。

> 元认知教训：**「从未跑通过的旧代码」不能假设只有一处问题**，修复后要一路验证到预期结果出现为止。

## 3. 当前架构与已知限制

- **前端抽帧只覆盖 4/12 容器**（mp4 / m4v / mov / webm = P0 已能播的那批）；
  其余 8 种（mkv / avi / flv / ts / 3gp / wmv / mpg / mpeg）**没有封面**，等 P1.5-B。
- **规模化瓶颈（4500 文件夹实测暴露）**：抽帧是「卡片挂载驱动 + 前端串行队列」——
  没有视口优先级、没有批量合批、没有后台预生成。已做的缓解：在途去重、60s 失败负缓存、体积感知超时。
  **终解是把封面生成挪进 Rust 的 `get_thumbnails_batch` 管线**（图片缩略图已在这套管线上跑通 4500 文件规模：
  rayon 并行 + 信号量限流 + 视口优先合批 + 可中断）。
- 抽帧时间点：10% 位置起步 + 近黑帧后移（最多 4 次），**不得取 t=0**（设计方案 §11.2 实测数据）。
- 已删掉本轮所有 `[VideoCover]` 临时诊断日志（项目惯例：取证后删除）。

## 4. 下一步：P1.5-B（指挥官已拍板的约束）

1. **系统有 ffmpeg 就直接用系统的；没有才下载**。
2. **只有 Web 解不了的 8 种容器走 ffmpeg**；mp4/m4v/mov/webm 继续走前端抽帧。
3. **⚠️ 绝对不能用 `ffmpeg-sidecar::auto_download()` 的默认源**：它拉的是 **gyan.dev 构建，
   页面原文 "All builds are 64-bit, static and licensed as GPLv3"，essentials 含 libx264/libx265/libxvid**；
   我们是 MIT → 直接分发触发 GPL 义务。**gyan 没有 LGPL 变体**。
   要保 LGPL 必须绕开其下载器，自行固定 **BtbN `win64-lgpl-shared`**（9.0，exe + DLL 约 73.7 MiB）。
4. 用 `ffmpeg-sidecar` 时 `default-features = false`（依赖只剩 anyhow）+ `FfmpegCommand::new_with_path()`；
   **下载目标必须是 `%LOCALAPPDATA%\com.aurora.gallery\ffmpeg`**，绝不能是 Program Files（UAC 拦截）。
5. 抽帧 `-ss` 放 `-i` 前（输入侧 seek）+ `-frames:v 1` + `scale=`；remux `-c copy`（无编码器依赖 → 不踩 GPL）。
6. 可选增强（待拍板）：仿 `color_worker` 的后台任务 + 进度弹窗，做**文件夹级封面预生成**，
   不用让用户滚完 4500 个文件。

## 6. 关键约定速查（动相关代码前必读）

- **非图片文件绝不进图片渲染管线**（记忆 §2.1）：`<img src=视频>`、把视频路径写进缩略图缓存、
  `convertFileSrc` 的图片 fallback——三个都不行。视频封面必须是**抽出的 JPEG 路径**，失败一律降级占位。
- **asset:// 画到 canvas 必须加 `crossOrigin`**（记忆 §2.4）：Tauri 2.11.6 asset 协议对每个响应都写
  `ACAO: <window_origin>`（Windows = `http://tauri.localhost`，与页面源精确吻合）→ 加 `anonymous` 合法且不影响播放。
  Range 单次上限 1 MiB（`asset.rs:119`），这也是 §14.7 那个 spinner 闪动的成因，属机制非 bug。
- **`ColorDbPool` 是单连接 + Mutex**（记忆 §2.6）：持锁期间绝不能再调任何池方法（会自死锁）。
- **TS→Rust 嵌套结构传参要 snake_case**（记忆 §8）。
- **流式播放不受文件大小限制**：`<video>` 走 asset 协议 Range 分片，不整文件读内存。
  不要凭「大文件=风险」设门槛（本轮因此误设过 512MiB / 2GiB，已全部取消）；
  真正的保护是**悬停意图延迟**与**超时**，不是体积。
